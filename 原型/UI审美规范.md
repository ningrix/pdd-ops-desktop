## 二、软件工程流程（硬规矩）

1. **token 分层，禁止页面里写死值**
   ```
   第一层 原始值   --m-fast:120ms  --r-md:8px  --accent-strong:#3b5fd9
   第二层 语义     --ease-std / --ease-decel / --ease-accel / --ease-spring
   第三层 组件     .btn / .fin-card / .rt-tabs —— 只引用上面两层
   ```
   页面级 CSS 里出现 `#4b7bec`、`220ms`、`8px` 这种字面值 = 违规。

2. **每个改动一条可执行断言**
   不是「看着对」，是脚本能量到的：`getComputedStyle` 取到某个值、`animationstart` 计数、
   节点数上限、对比度 ≥4.5。没有断言的设计改动一律视为没做完。

3. **单步可回退**
   每块动效/样式独立成段（`/* UI-XX ... */`），提交信息写清「改了哪几处、怎么验的」。
   出问题 `git revert` 单条，不要整轮回滚。

4. **改完必跑三件套**
   ```
   node work/zcode-验收-app-UI.mjs          19 PASS
   python tools/ui_perf_check.py --strict   7 项
   python work/capture_window_max.py        截图人看
   ```
   截图不能省 —— 断言能过但视觉很丑的情况真实存在（白滑块贴白页就是）。

## 三、社会心理学（决定优先级与动效）

| 现象 | 结论 | 本应用怎么做 |
| --- | --- | --- |
| **序列位置效应** | 排在前面的天然获得第一眼注意力 | 列表错峰入场 40ms/行，把阅读顺序排给眼睛；总时长封顶 300ms |
| **变化盲视** | 静态数字跳变，人看不见「变了多少」 | 金额滚动 500ms；滚动中 `tabular-nums` 防抖宽 |
| **损失厌恶** | 损失比收益更刺眼，红色只留给钱 | `.expense` 只用于金额；状态标签用中性色或琥珀，不用红 |
| **目标梯度效应** | 越接近目标越有动力 | 采集进度环显示 N/M；结束亮满格 600ms 再收 |
| **Hick 定律** | 选项越多决定越慢 | 一屏只留一个实心主按钮（`btn.primary`），其余描边或幽灵 |
| **蔡格尼克效应** | 未完成的事更占注意力 | 未完成项做「慢脉动」提示，不要用高频闪烁（会烦） |

**反例（我踩过）**：给整屏 `.pane` 加滑入 —— 面积太大，软件渲染掉帧，用户第一感受是「卡」而不是「丝滑」。
**动效只在面积小的元素上做**（行、按钮、圆环、药丸滑块）。

## 四、政治经济学（决定信息立场）

这个工具的存在理由是：**平台和商户之间信息不对称**。界面立场要站在「商户能逐笔核对」这一边。

- **账本式克制**：金额右对齐、等宽数字、千分位；不要用渐变、不要用插画去「美化」数字。
- **口径必须写明**：一个数是从哪来的，副行写清楚。例：
  - 「未结算金额 18,411.70 / 72 单在途 · **按订单估算**」
  - 因为平台货款账户页没有「待结算」这一个数，精确值只在**对账中心**按单列。
  - 把估算说成平台口径 = 欺骗用户，比数字不准更糟。
- **不隐藏不利信息**：退款、货损、平台费要和收入同等显眼，不能折叠进「更多」。
- **注意力是稀缺资源**：顶部四张卡只放「能改变决策」的数，不放「最近到账」这类过程指标。

## 五、iOS HIG（决定视觉与手感）

三条原则：**clarity（清晰）/ deference（退让）/ depth（层次）**。

| HIG 要求 | 本应用落地 |
| --- | --- |
| **deference**：chrome 退让，内容说话 | 页头标题删掉（侧栏已有页名）；bar 高 44px；卡片白底细边，不抢数字 |
| **clarity**：白底、清晰边界、语义色 | 方向 D：`--bg #f4f6fa` / `--panel #fff` / `--line #dde5ee` |
| **语义色过 AA** | `#0f7a4d` 收入 / `#c0392b` 支出 / `#96601a` 警告；实心按钮底用 `--accent-strong`（白字 5.5:1），不用 `--brand`（3.5:1） |
| **触达尺寸** | 行内可点控件 ≥24px；图标按钮 26–32px；不要做 16px 的可点区域 |
| **分段控件是两层** | **灰色轨道 + 白色滑块**。只有白滑块 = 白底上看不见（这次真实踩到） |
| **键盘可达** | `:focus-visible` 必须有可见环，且不能用 `outline:none` 裸删 |
| **减少动态效果** | `prefers-reduced-motion: reduce` 时全部动画关闭 |
| **深度用阴影不用模糊** | 卡片 `0 1px 2px rgba(16,32,64,.05)`；**禁 backdrop-filter**（软件渲染又慢又脏） |

### 分段控件的正确结构（这次改了三次才对）

```css
/* 轨道 */
.rt-tabs { display:inline-flex; gap:2px; padding:3px; border-radius:999px;
           background:#eceff4; border:1px solid #e2e7ef; }
/* 滑块：内缩对齐轨道 padding */
.rt-thumb { position:absolute; top:3px; left:3px; height:calc(100% - 6px);
            border-radius:999px; background:#fff;
            box-shadow:0 1px 2px rgba(16,32,64,.12); }
/* 只留一种选中标识：药丸 or 下划线，不要两个都留 */
```

## 六、数字与排版的比例（可直接抄）

| 元素 | 值 | 依据 |
| --- | --- | --- |
| 卡片数值 | 30px / 600 / `-.2px` 字距 | 主数字要能一眼读出量级 |
| 卡片标签 | 13px muted | 比数值小 2.3×，形成主次 |
| 卡片副行 | 12px muted，**强制单行** | 折行会把四张卡撑得高低不齐 |
| 表格正文 | 12.5px | 再小中文发虚 |
| 表头 | 11px / 600 muted | 表头是标签不是内容 |
| 行内小字（/26、23/26、29.9%） | 10.5px，紧跟主值 | 少一行高度，信息不丢 |
| 卡片内边距 | 18/20 | 8pt 节奏，留白给数字让位 |
