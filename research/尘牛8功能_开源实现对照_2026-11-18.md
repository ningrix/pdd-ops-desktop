## 二、逐个说，附具体项目链接

### 1️⃣ 产品裂变 —— 没现成的，但对我们最简单

**它做什么**：同一款货，生成多个不同标题/主图的商品，「铺」成矩阵，
分摊单链接的比价压力和重复铺货判定。

**GitHub 上有没有**：没有直接对应的开源项目。**但这不是难点** ——
它本质就是「同一批数据 → N 个变体 → 调 N 次发布接口」。

**我们的实现路径**（用现有代码就能拼）：

```
采集箱数据包
  ├─ 变体生成器：标题换词序 / 换卖点前置 / 换同义词
  ├─ 主图变体：换首图顺序 / 换背景色 / 加不同卖点角标
  └─ 对每个变体：走已有的 pool:publish
```

**唯一天花板**（这条必须记住）：
`600102 该商品已被新建过` —— 平台对同一 goods 的新建有次数限制。
所以裂变只能基于**不同的源商品**，不能靠同一款无限复制。

**成本**：2 小时（变体生成纯字符串处理 + 复用现有发布链路）

### 2️⃣ 批量编辑 —— 平台自带一个，我们要做的是「跨商品」

**拼多多自带**：编辑页有「Excel批量编辑规格」，能导出现有 SKU、改完导回去。
**但**它只能改**同一个商品内**的 SKU（库存/价格/编码/状态），
**不能跨商品批量改**。

**GitHub 上有**：无直接对应。这和上面「产品裂变」一样，是编排型功能。

**要做的三件事**：

| 能力 | 现状 | 做法 |
|---|---|---|
| 跨商品批量改价 | 已有 `ops:changePrice` | 加个列表循环 + 频率控制 |
| 跨商品批量改标题 | 需新增 | 抓载荷 → 换 `goods_name` → 回放 |
| 跨商品批量改库存 | 机制明确（`quantity_delta`） | 同上 |

**关键约束**（AGENTS.md §8 已写）：批量开关之前必须先修两个 bug
（`#copyFactor` 无监听、复制按 idx 不校验 goods_id），否则会批量改错商品。

**成本**：1 天

### 3️⃣ 商品检测 —— 拼多多官方就有，别自己写规则

**官方接口**（从 open-pdd-net-sdk 查到）：

```
pdd.goods.cat.rule.get      {cat_id}    → 该类目的全部规则（必填属性、禁词、图规格）
pdd.goods.sizespec.meta.get {class_id}  → 尺码表参数定义
```

MMS 内部也有对应的体检入口：`/gear/inspect`、`goods_inspect_score`
（**未确认**：这两个是我之前调研看到的路径，未实测通过，需抓包验证）

**检测的四个维度**（都是我们能算的）：

| 维度 | 数据来源 | 判定 |
|---|---|---|
| 必填属性缺失 | `cat.rule` 的 required 字段 vs 商品 `goods_properties` | 直接比对 |
| 标题违规词 | 平台违禁词库 | 需要词库（**未确认**：官方未公开完整词库，只能用公开整理版） |
| 主图规格 | 宽度/高度/大小/张数 | 下载图算 |
| SKU 完整性 | 每个 SKU 是否有价、有库存、有图 | 本地校验 |

**这条我要明确说**：违规词库**没有官方公开版本**，市面上的都是整理的，
准确率未知。我的建议是**只报「疑似」，不做「一定违规」的断言**，
避免误伤你的正常商品。

**成本**：半天

### 4️⃣ 标题AI优化 —— 不是技术问题，是提示词问题

**技术实现**：一行调用。已有 LLM，不需要额外依赖。

**真正的难点是「优化什么」**。拼多多标题的硬规则：

```
60 字上限 ｜ 前 10 字权重最高 ｜ 禁堆砌 ｜ 类目相关词必须出现
```

**可用的开源参考**：
- `SpecFusion`（102★）—— 能查拼多多官方 API 文档，写提示词时查规则用
- 现成的电商标题 prompt 模板很多，但**平台规则部分必须自己校**

**我的建议**：做成「**给 3 个候选 + 标出字数/关键词覆盖**」，不做全自动替换。
因为标题是流量的核心，全自动太危险。

**成本**：2 小时

### 5️⃣ 主图优化 —— 这个我们做完了

你已经有 **70+ 张成品图**在 `交付/` 目录，管线是：

```
去标（RapidOCR 定位）→ 去水印（LaMa 修补）→ 4x 超分（Real-ESRGAN）→ 白底
CPU 15~25 秒/张
```

**对比尘牛的「主图优化」**：它大概率是调个滤镜 + 自动裁剪 + 加边框。
**我们的管线比它强**（有超分和修补）。

**这条结论：不用再投入，已经领先。**

### 6️⃣ 主图视频 —— 唯一一个我认为值得重点投入的

**为什么重要**：拼多多商品带视频，转化率提升明显（这是行业共识，
但**具体提升多少我没有官方数据，标为未确认**）。

**开源方案**（按推荐度排序）：

| 方案 | 项目 | 适合度 |
|---|---|---|
| **图片轮播 + 转场 + 背景音乐** | FFmpeg（`zoompan` + `xfade` filter） | ⭐⭐⭐ **最适合我们** |
| AI 图生视频 | Stable Diffusion + AnimateDiff | ⭐⭐ 效果炫但慢、贵、不可控 |
| 万相 Wan2.1 / LTX-Video | 开源视频模型 | ⭐ 需要好显卡，本机跑不动 |

**我推荐 FFmpeg 方案**，理由：

```bash
# 把 5 张主图做成 8 秒短视频（缩放推进 + 交叉淡入）
ffmpeg -loop 1 -t 1.6 -i img1.jpg -loop 1 -t 1.6 -i img2.jpg ... \
  -filter_complex "[0]scale=1600:-1,zoompan=z='min(zoom+0.0015,1.15)':d=40[a0]; \
                   ... [a0][a1]xfade=transition=fade:duration=0.4:offset=1.2[out]" \
  -map "[out]" -c:v libx264 -pix_fmt yuv420p out.mp4
```

**优点**：
- 零 AI 依赖，CPU 跑，一台机器一分钟出 20 条
- 完全可控（时长、转场、节奏都能调）
- 无版权风险
- **不违反「不引入原生编译依赖」**（FFmpeg 是外部可执行文件，不是 npm 原生模块）

**拼多多视频规格**（需实测确认）：一般是 1:1 或 3:4，时长 ≤ 60 秒，≤ 100MB。

**成本**：2~3 天（含格式适配 + 批量队列）

### 8️⃣ 主图水印 —— 能做，但我要说清楚它能干什么、不能干什么

**开源方案很多**：

| 项目 | 星数 | 语言 | 说明 |
|---|---|---|---|
| `hzbd/imagekit` | 182★ | Rust | 批量图片处理，含水印，速度快 |
| `xomvio/watermarker` | 22★ | Rust | 极简 CLI，依赖少 |
| `react-native-image-marker` | 370★ | TS | 支持文字/logo/平铺/批量 |
| `jasimmk/watermarker` | 68★ | Python | Python 系里最直接的 |

**但这里必须讲清一件事**（AGENTS.md §1.2.6 也写了这条）：

> **加个水印 / 换个色调**，**不能**用来躲开平台的重复铺货判定。
> 平台的图像指纹判定不看这个 —— 它算的是图像感知哈希，加一行字不影响。

**水印真正有用的地方**：

| 用途 | 有效 |
|---|---|
| 打自己的品牌标，防同行盗图 | ✅ 有效 |
| 加卖点角标（「顺丰包邮」「7天无理由」） | ✅ 有效，能提升点击 |
| 遮住友商 logo | ✅ 有效 |
| **躲开重复铺货检测** | ❌ **无效** |

**成本**：2 小时（Python + Pillow，做个 CLI）

## 三、我建议的优先级

考虑到你的实际情况（自用 + 给团队，要省钱）：

| 优先级 | 做什么 | 为什么 | 工时 |
|---|---|---|---|
| **P0** | **把「改规格」这条打通** | 这是所有功能的地基。跨店不能搬规格 = 整个工具没用 | 半天~1天 |
| **P1** | **批量编辑** | 你现在一次只能弄一个商品，这是最痛的 | 1 天 |
| P2 | 主图视频（FFmpeg） | 唯一能直接提升转化的 | 2~3 天 |
| P3 | 商品检测 | 避免违规下架，但词库不准 | 半天 |
| P4 | 产品裂变 | 得先有 P0+P1 才有意义 | 2 小时 |
| P5 | 标题优化 | 有价值但容易帮倒忙 | 2 小时 |
| P6 | 水印 | 就是加个品牌标 | 2 小时 |

**注意 P0 是前置**。现在跨店上架过去规格是错的，批量跑 50 个就是 50 条废品。

## 四、关于尘牛本身的价值判断

看完这 8 个功能，我的结论更明确了：

| 尘牛的功能 | 它的实现 | 我们的替代 |
|---|---|---|
| 全部 8 个 | 拼多多官方 API + 编排 | 我们自己走 MMS 内部通道 |
| 它的护城河 | **企业 ISV 资质** + 服务市场入口 | 不需要，我们有登录态 |

**它卖的不是技术，是资质 + 省事。** 它每个功能的技术难点都不高，
难的是「不用自己写」。

**这就是它值钱的原因，也是我们不该买它的原因** —— 我们已经在写了，
而且地基（复制、改价、改库存、提交上架、多店铺、登录持久化）都通了。

## 五、一句话

> 8 个功能里，**2 个你已经做完了（多店铺、主图优化）**，
> **4 个有现成开源方案（水印、视频、检测、标题）**，
> **1 个是编排（批量编辑）**，**1 个纯拼装（产品裂变）**。
>
> 没有一个是需要逆向尘牛才能知道的。
> 真正的瓶颈还是那一件事：**跨店搬规格**。
