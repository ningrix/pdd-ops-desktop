## 二、跨店是怎么做到的

`copyGoodsCommit` 只能克隆**本店**商品，所以跨店不能直接搬。用「骨架 + 覆盖」绕过去：

```
① 在目标店铺挑一条它自己的在售商品当「骨架」
② 克隆骨架 → 得到一个属于目标店的草稿（图/SKU/类目都是目标店合法的）
③ 抓这个草稿的保存载荷（主进程内 webContents.debugger，比外部 CDP 稳）
④ 用采集箱的数据覆盖字段：
     goods_name  ← 源标题
     galleries   ← 源主图（img.pddpic.com 的公开 URL，跨店可用）
     skus[].multi_price / price ← 源价格
     skus[].quantity_delta      ← 库存
⑤ 回放 action/edit 保存
⑥ 读页面 commit → commit/submit 提交
```

关键点：**骨架保证类目/属性/规格是目标店合法的**，我们只替换可变字段，所以不会被类目校验拦。

## 四、已知局限（下一步要补）

| 项 | 现状 |
|---|---|
| 标题 | ✅ 来自源 |
| 主图 | ✅ 来自源（12 张） |
| 价格 | ⚠️ 源商品**最低拼单价**套到了所有 SKU（不是逐 SKU 对应） |
| **SKU 规格** | ❌ **仍是骨架的规格**（这次用到了羽绒马甲的 25 个 SKU，不是登山鞋的 64 个） |
| 详情图 | ❌ 未覆盖（仍是骨架的） |

**SKU 规格映射**是下一个重点：源商品 64 个 SKU（36~45 码），骨架 25 个（2/4/6/8/10 码）。要正确搬运，得按规格名匹配或重建 SKU 树——这需要改 `action/edit` 里的 `skus` 与 `groups` 结构，比改标题难一层。
