# 采集会话：读别人的商品链接（已做进应用）

> 2026-11-18

---

## 一、做好了什么

新增第 3 个页签 **「采集会话」**（页签顺序：商品列表 / 采集箱 / **采集会话** / 店铺后台 / 原始结果）。

打开后是一块独立的浏览器，**有自己的登录态，和你的两个店铺完全隔离**（不同 cookie 分区，操作互不影响）。

界面上有一个地址栏：

```
[粘贴别人的商品链接                          ] [打开] [读取商品]
首次使用：在下方浏览器里用手机号登录一次买家账号
```

---

## 二、你只需要做一步

**在「采集会话」的浏览器里登录一次买家账号。**

实测：打开任何商品链接都会跳到登录页

```
https://mobile.yangkeduo.com/login.html?from=...goods.html?goods_id=...
页面：打开拼多多APP / 手机登录 / 发送验证码
```

登录方式（选一个）：
- **手机号 + 验证码**（页面上直接有）
- 或者用手机拼多多 App 扫码

**登录一次，之后一直有效**（登录态存在 `persist:collector` 分区里，正常关窗口不会丢）。

这一步只能你做——验证码发到你手机上。

---

## 三、之后怎么用

```
① 粘链接 → 点「打开」
② 等页面加载出来
③ 点「读取商品」
④ 自动存进采集箱（来源标记为「外部链接」）
⑤ 去「采集箱」页，走原来的上架流程
```

读取时会抓这些：

| 字段 | 来源 |
|---|---|
| 标题 | `window.rawData.store.initDataObj.goods.goodsName`，读不到就从页面 DOM 兜底 |
| 主图 | 同上 `gallery`，兜底抓页面里 `pddpic.com` 的图 |
| 拼单价 / 参考价 | 同上，兜底从页面文字里正则取 `¥` 价格 |
| SKU 规格 | 同上 `skus`，解析出颜色 / 尺码 |
| 类目 | 同上 `catName1~4` |

**采集箱里的外部商品，`sourceMallId` 标为 `__external__`**，所以不会被误判成"同店复制"而拦下。

---

## 四、但上架那端的能力没有变化

这是必须说清的：

| 步骤 | 状态 |
|---|---|
| 读别人商品（标题/主图/价格/SKU） | ✅ 已做，需要买家账号登录 |
| 存进采集箱 | ✅ 已做 |
| **上架到你的店** | 还是只有两条路：骨架克隆 / 空白新建 |
| **自定义尺码** | ❌ 依然不行（网页端没自由入口） |

也就是说：**采集这半段通了，发布那半段和之前一样。**

从别人的商品上架到你的店，具体会是这样：
- 如果目标类目你店里**有同品类商品** → 可以走骨架克隆
- 如果没有 → 要走空白新建（标准尺码可以，自定义尺码不行）

---

## 五、如果读取失败

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 提示「需要登录」 | 采集会话还没登录 | 在下方浏览器里登录一次 |
| 提示「没读到商品数据」 | 页面结构和我猜的不一样 | 把链接发我，我调解析规则 |
| 标题/图读到了但 SKU 是空的 | 该商品没有规格，或结构特殊 | 可以先上架再手动补规格 |

**`rawData` 的真实结构我是按经验猜的**（`store.initDataObj.goods`），
如果你登录后读出来的字段对不上，把「原始结果」页签里的内容发我，我按真实结构改。

---

## 六、用完记得清草稿

外部链接采集进来的商品，上架失败会留草稿。

采集箱页有清理能力（`draftsList` / `draftsDelete`），或者告诉我，我跑一次全清。

---

## 七、一句话

> **采集会话已经能用**：粘链接 → 读取 → 进采集箱。
> 你只需要在它的浏览器里**登录一次买家账号**（验证码发你手机）。
>
> 但上架那端还是原来那两条路 —— 采集通了不等于发布通了，
> 自定义尺码仍然是唯一补不上的缺口。
