## 二、商品检测

### 分两层，第一层不读图

```
① 规则层（纯 Node，零依赖，瞬时）
   标题长度 / 营销套话堆砌 / 连续重复片段
   SKU 价格逻辑（单买价必须 > 拼单价）
   SKU 规格完整性
   参考价必须严格大于最高单买价   ← 实测规则 1000161，相等也会被拒
   主图数量 / 重复
   尺码表有无
   类目 id / 类目名

② 图像层（Python，下载主图逐张量，约 2 秒/张）
   尺寸、比例、文件体积
   白底纯度（四角+边缘采样）
   主体占比、主体居中偏移
   文字覆盖面积（需 rapidocr，未装则跳过并提示）
```

### 三级分类，不误伤

| 级别 | 含义 | 例子 |
|---|---|---|
| **error 必修** | 平台会拒或一定有问题 | 标题超 60 字、参考价低于单买价、SKU 价格倒挂 |
| **warn 建议改** | 影响流量/审核 | 主图重复、主图少于 5 张、标题含 3+ 个套话 |
| **info 参考** | 可能是数据缺失或个人选择 | 没尺码表、类目名没采到、非白底 |

**所有没有官方依据的阈值都标了 `未确认`**（界面上显示灰字「未确认」），
按 AGENTS.md §1.3.3 的要求，不把经验值当规则。

### 实测结果（9 条真实商品）

```
共 9 条 | 必修 0 | 建议 9 | 干净 0
  84 分  轻量化5000gt羽绒服   主图重复 8 张、没读到尺码、没尺码表、类目名缺失
  92 分  远征5系列登山鞋      主图重复 6 张、没尺码表、类目名缺失
  ...
```

### 检测立即抓到的真实 bug

**拼多多的图集接口返回重复 URL。** 实测：

```
一条商品 gallery list[21] → 唯一 URL 只有 11 个
另一条 gallery=13 → 唯一 7 个
```

后果：
1. 上架后主图有大量重复图位，浪费曝光
2. 加水印时重复处理同一张图（浪费一半时间）

**已在两处修**：
- `ops.collectGoods`：采集时去重（新数据）
- `lib/pool.js` 的 `load()`：读取时再兜一层（旧数据也生效）

修后验证：13 张 → **7 张**，水印耗时从 13 张降到 7 张（1441ms）。

## 三、主图水印

### 三种模式（实测都有样张）

| 模式 | 效果 | 用途 | 耗时 |
|---|---|---|---|
| **角标** | 四角之一，一行字 | 品牌标，不挡商品 | 36ms |
| **平铺** | 斜向重复低透明度 | 防盗图 | 178ms |
| **卖点条** | 底部半透明色带+居中白字 | 「顺丰包邮 \| 7天无理由」 | 35ms |

### 关键设计：自适应深浅色

**第一版是白字，在白底商品图上几乎看不见** —— 拼多多主图绝大多数是白底，这是致命问题。

修法：取文字背后区域的平均亮度，白底切深灰、深底切白色。

```python
return dark if _luma_mean(img, box) >= 150 else light
```

修后白底上出深灰字，清晰可读。样张见 `交付样张/主图处理演示_2026-11-18/`。

### 卖点条调优过一轮

第一版 8.5% 高度 + 55% 不透明，**遮住了商品图底部的颜色标签**。
改成 6.5% + 50% + 加一条 1px 白色细线分隔 + 文字加阴影，既显眼又不挡关键信息。

### 输出方式（要明确的边界）

```
采集箱条目 → 下载主图 → 加水印 → 输出到
app\userdata\watermarked\<条目id>_<时间戳>\wm_01.jpg ...
```

界面上给「打开文件夹」按钮直接看成品。

⚠️ **不会自动替换平台上的图**。原因是「图片上传接口」在 AGENTS.md §4 里仍是
**未确认项** —— 我们还没抓到上传接口。所以现在是「生成好本地图，你自己上传替换」。

这是诚实的边界，不是偷懒。

## 四、技术栈落地情况

```
tools/imgtool/
├─ models.py       ✅ 手写 RRDBNet（80 行，零 basicsr）
│                    实测：加载 RealESRGAN 权重 missing=0 / unexpected=0
├─ upscale.py      ✅ 4x 超分，支持分块 tiling
├─ watermark.py    ✅ 三模式 + 自适应深浅色
├─ inspect_img.py  ✅ 尺寸/白底/居中/文字覆盖
└─ __main__.py     ✅ CLI，JSON 输出，--json 两个位置都能用

app/lib/inspect.js  ✅ 规则层，纯 Node
app/lib/imgtool.js  ✅ spawn 封装，失败分类严格按 §5
```

### 依赖变化（重要）

| 项 | 变化 | 原因 |
|---|---|---|
| **Pillow** | 9.5.0 → **11.3.0** | 9.5.0 在本机 `draw.text()` 直接崩 `0xC0000005`（ACCESS_VIOLATION），连纯 ttf 都崩 |
| simple-lama-inpainting | **已卸载** | 要求 pillow<10 会把版本拖回去；LaMa 预处理我们手写 |
| basicsr | **不装** | 手写 RRDBNet 完全替代 |
| rapidocr-onnxruntime | **未装** | 文字覆盖检测用它，装了就启用，不装则该检查项跳过 |

### 一个坑：`-m` 需要 `__init__.py`

`python -m tools.imgtool` 要求 `tools/` 和 `tools/imgtool/` 都有 `__init__.py`，
否则 `__main__.py` 里的相对导入会报 `attempted relative import with no known parent package`。

## 五、怎么用

### 界面

1. 切到「采集箱」页
2. 每行点 **检测** → 弹窗出报告
3. 报告里点 **连主图一起查** → 追加图像层（多花 2~3 秒/张）
4. 每行点 **水印** → 填文字、选模式、调浓度 → 生成 → 打开文件夹

### 命令行

```bash
python -m tools.imgtool inspect  --in a.jpg --json
python -m tools.imgtool inspect  --in a.jpg --ocr --json     # 带文字检测
python -m tools.imgtool watermark --in a.jpg --out b.jpg \
        --text "山野户外旗舰店" --mode corner --pos br --opacity 0.55
python -m tools.imgtool watermark --in a.jpg --out b.jpg \
        --text "顺丰包邮" --mode band --opacity 0.5
```
