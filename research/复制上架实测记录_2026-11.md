## 二、完整 API 链（实测）

```
① POST /vodka/v2/mms/query/display/mall/goodsList
   body: {page, size, is_onsale:1, pre_sale_type:4, shipment_time_type:3, sold_out:0}
   → goods_list[].id = goods_id

② POST /glide/v2/mms/edit/commit/create_by_sn
   body: {goods_id}
   → { goods_commit_id, old_goods_commit_id, commit_check_status }
   ⭐ 这一步是之前缺的关键环节。「编辑」按钮点的就是它

③ POST /glide/v2/mms/edit/commit/copyGoodsCommit
   body: {goods_id, goods_commit_id}
   → { goods_commit_id: 新草稿, goods_id: 新商品, mall_id, goods_sn }
   ⭐ 图/SKU/模板 全部继承，不用自己传

④ POST /glide/mms/goodsCommit/action/update_goods_commit_info
   body: {goods_commit_id, goods_name, cat_id}
   ⚠️ 必须带 cat_id；禁止传 out_goods_sn（会触发「类目信息为空」更严校验）

⑤ POST /glide/v2/mms/query/commit/detail
   body: {goods_commit_id}
   → 完整商品对象（回读校验用）

⑥ POST /glide/v2/mms/edit/commit/submit
   body: {goods_commit_id}
   → 公开上架（单次调用，失败不要盲重试）
```

**「编辑」页的真实 URL**：`/goods/goods_add/index?id=<goods_commit_id>&goods_id=<goods_id>&type=edit`
—— 也就是说，URL 里的 `id` 就是 `commit_id`，这也是个拿 commit_id 的备用手法。

## 三、字段真相（这部分外面没人公开写过）

### 商品列表 `/goodsList`
| 你以为的 | 实际字段 |
|---|---|
| `goods_id` | **`id`** |
| `goods_commit_id` | **不存在**，得靠 `create_by_sn` 拿 |
| 拼单价 | `sku_group_price`（**数组**，单位：分） |
| 单买价 | `sku_price`（数组，分） |
| 市场价 | `market_price`（分，标量） |
| 库存 | `quantity` |

### 草稿详情 `commit/detail`
| 项 | 实际字段 |
|---|---|
| 提交 ID | **`id`** = goods_commit_id |
| 商品 ID | `goods_id` |
| 是否草稿 | `is_shop === 0` |
| 图片组 | **`galleries`**（数组，每项含 url/width/height/file_id/type） |
| SKU 列表 | **`sku`**（扁平数组，不是分组） |
| 单买价 | `price`（分） |
| 拼单价 | `multi_price`（分） |
| 库存 | `quantity` |
| 规格 | `spec` |
| 属性 | `goods_property_list` |
| 运费模板 | `cost_template_id` |
| 发货时效 | `shipment_limit_second`（秒） |

⚠️ `price_in_yuan` / `multi_price_in_yuan` 在 detail 里是 `null`，**别用它们算钱**，用 `price` / `multi_price` 除 100。

### 你店里现成的定价规律（从 6 个商品看出来的）
```
单买价 ≈ 拼单价 × 1.10
市场价 = 单买价 + 1.00 元
```
例：33088 → 36397 → 36497（分）＝ 330.88 → 363.97 → 364.97（元）

这个规律可以直接做成定价引擎的默认模板。

```

```
启动独立 profile 的工作浏览器 + CDP 端口 9222，然后扫码登录一次。之后永久有效。

### 日常命令

```powershell
# 列出在售商品（带 idx / goods_id / 价格 / SKU数 / 库存）
python tools\pdd.py list

# 复制第 N 个商品成草稿（图/SKU 全继承，可改标题）

# 查草稿详情

python tools\pdd.py submit --goods 1030243408035 --commit 206366952022
```

`copy` 默认只到草稿；加 `--submit` 才真上架。

## 八、下一步：把「改价 / 改库存」打通

`update_goods_commit_info` **只认 `goods_name`**，改价和改库存走不通这条路。要用同一套手法抓：

```
1. 在编辑页手动改一个 SKU 的价格，点保存
2. 同时用 tools/cdp_capture.py 抓包
3. 找到真正的保存接口和 body 结构
4. 加进 pdd.py
```

工具已经就位，抓包一条命令：

```powershell
python tools\cdp_capture.py --nav "https://mms.pinduoduo.com/goods/goods_add/index?id=206366952022&goods_id=1030243408035&type=edit" --seconds 20 --match commit,edit,save,sku,price,update
```

你手动改一次价并保存，我拿抓包结果就能把改价接口定下来。

打通之后，`copy` 就能变成完整的「复制 → 补库存 → 改价 → 改标题 → 上架」，一条命令搞定一个商品，这才是能给你团队用的东西。
