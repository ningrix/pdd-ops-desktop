## 一、UI 两个问题：已修

### 根因是 UA 设错了

之前我给采集会话设了 **iPhone UA**，拼多多判定「你在手机浏览器里」，于是跳到 App 下载引导页：

```
.../down_download.html?need_popover=true&add_download_task=1
   &should_download=true&refer_page_name=market_download
```

那个页面就是「正在跳转...」，而且永远不会结束。

同时因为视口宽度是 843px、页面按 `width=device-width` 布局，手机站被拉宽到 843px，所以元素显得巨大。

### 修法

改成**桌面 Chrome UA**：

```
Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
(KHTML, like Gecko) Chrome/144.0.0.0 Safari/537.36
```

### 修后实测

```
✓ 不再跳下载页
✓ 稳定停在登录页，且两种方式都有：手机登录 / 扫码登录
   （之前只有「手机登录」，因为手机 UA 不给扫码）
✓ 页面按正常宽度渲染
```

另外加了一道保险：`will-navigate` 里拦下任何 `down_download` / `app_download` / `market_download` 的跳转，不再让它跑飞。

## 二、「AI添加规格」实测：点了没反应

### 元素本身是好的

```
BUTTON.BTN_outerWrapper_5-194-0 BTN_secondary
  w=113 h=28  disabled=false  含 svg 图标
```

### 三种点击方式都试过

| 方式 | 结果 |
|---|---|
| JS `el.click()` | clicked，无变化 |
| Playwright `getByText('AI添加规格', {exact:true}).click()` | OK，无变化 |
| `click({force:true})` 真实鼠标事件 | OK，无变化 |

### 点击后页面状态（实测）

```
颜色：        []                                    ← 空的
已勾选码值：   ["7天无理由退货"]                      ← 那是服务勾选，不是尺码
SKU 行数：    1
尺码选项：    150/72A … 180/112A  全部未勾选
新增弹层：    无
新增输入框：  无（只有原本就在的那些）
```

**结论：这个按钮在当前账号/环境下点下去没有任何效果。**
可能原因（都未确认）：
- 需要前置条件（比如先有颜色规格）
- 灰度功能，这个账号没开
- 依赖的服务不可用

**不管哪种，它不能用来创建自定义尺码。**

## 三、自定义尺码：最终结论

### 网页端四个入口全部排除

| 尝试 | 结果 |
|---|---|
| 7 种标准码制（通用/中国码/欧码/英码/德码/美码/均码） | ❌ 只有标准码值，如 150/72A |
| 「自定义尺码」输入框 | ❌ 输入后出现的是 `肩宽/胸围/臀围/身高/体重/腰围` —— 这是**尺码表的列定义**，不是尺码值 |
| 「全部尺码表」 | ❌ 跳转到 `/goods/size/list`（尺码表管理页），不是选模板 |
| 「AI添加规格」 | ❌ 点了没反应 |

**网页端确实没有任何地方能创建 `2（90-100）` 这种自定义尺码值。**

### 浏览器插件为什么也不行

插件只能操作**页面上已经存在的元素**。
既然页面上没有「输入自定义尺码」的输入框，插件就没有东西可点。
模拟人手点击也点不出一个不存在的入口。

**这不是技术选型问题，是入口不存在。**

## 四、但是有一个实际可行的替代方案

既然自定义尺码做不了，**把自定义码映射成标准码**：

### 原理

`2（90-100）` 这个标签实际表达的是「尺码 2，适合身高 90~100cm」。
它可以拆成两部分：

```
规格值（买家选的）  →  标准码：S / M / L / XL / XXL
                      （或 150/72A 这类国标号型）

尺码表（买家看的对照）→  身高 90~100cm → S
                      身高 100~120cm → M
                      ...
```

**这样买家看到的还是「S，适合 90-100cm」，体验几乎一样，但商品能上架了。**

### 映射规则

| 源标签 | 映射到标准码 | 尺码表里写 |
|---|---|---|
| `2（90-100）` | S | 身高 90-100 |
| `4（100-120）` | M | 身高 100-120 |
| `6（120-140）` | L | 身高 120-140 |
| `8（130-150）` | XL | 身高 130-150 |
| `10（140-160）` | XXL | 身高 140-160 |

（这只是示例，实际按你的商品尺寸表定）

### 代价

- 尺码标签变了（买家看到的从「2」变成「S」）
- 如果原商品靠「2/4/6」这种标签做差异化的，会弱化

### 收益

- **商品能上架了**，不用等入驻审核
- 尺码表里保留了身高体重对照，买家照样能选对码
