# 修复「添加店铺没反应」+ 打通改价接口

> 2026-11-16

---

## 一、Bug：点「添加店铺」没反应

**根因：Electron 的 renderer 不支持 `window.prompt()`。**

不是没生效，是一点就抛异常：`Error: prompt() is and will not be supported`。异常没人接，界面上就「什么也没发生」。`alert` / `confirm` 在 Electron 里是支持的，只有 `prompt` 被移除了。

**修法**：换成应用内置弹窗（`index.html` 里的 `#modalMask` + `app.js` 的 `askText()`），支持回车确认、Esc 取消、空值校验。

顺带把 `confirm()` 也收进 `askConfirm()`，以后要换实现只改一处。

同时修了左栏 `overflow: hidden` 导致内容超出窗口后无法滚动的问题 —— 改价按钮之前被挤到可视区外。

## 二、改价接口：通了

### 2.1 保存接口

```
POST /glide/mms/goodsCommit/action/edit
```

这是编辑页点「保存草稿」时打的接口。请求体 **67 KB**，一个 64 SKU 的草稿，字段 157 个顶层 + 21 个 SKU 字段。

**价格字段（单位：分）**

| 字段 | 含义 | 实测值 |
|---|---|---|
| `skus[].multi_price` | **拼单价** | 22888 |
| `skus[].multi_price_in_yuan` | 拼单价的元字符串 | "228.88" |
| `skus[].price` | **单买价** | 25177 |
| `skus[].price_in_yuan` | 单买价的元字符串 | "251.77" |
| `skus[].quantity_delta` | **库存增量**（SKU 里没有 `quantity`） | 22 |
| `market_price` / `market_price_in_yuan` | 市场价 | 25277 / "252.77" |
| `groups.group_price` / `groups.single_price` | 规格组价 | 0 / 0 |

### 2.2 实测结果（改价成功）

```
拼单价   22888 → 24032   (×1.05)  ✅
单买价   25177 → 26436            ✅
市场价   25277 → 26536            ✅
SKU 数   64 不变                  ✅
```

回读 `commit/detail` 确认三个价格都落库了，不是只改了前端。

### 2.3 通用做法（不用逆向 schema）

我试过两条路，第一条是死路：

| 路线 | 结果 |
|---|---|
| 从 `commit/detail` 直接构造请求体 | ❌ `4000000 请求method,argument,body错误`（detail 比编辑载荷多 50 多个字段） |
| 按编辑载荷的字段白名单投影 detail | ❌ `2000000 价格参数不完整`（和网上那份 flow 文档踩的是同一个坑） |
| **抓编辑页自己保存时的载荷，改完回放** | ✅ 稳定 |

所以最终实现是：

```
1. 打开该草稿的编辑页
2. 程序点一次「保存草稿」，同时抓 Network 拿到这份草稿的真实 action/edit 载荷
   （页面自己生成的载荷，天然合法，不用猜字段）
3. 在载荷上改 multi_price / price / market_price / quantity_delta
4. 回放 action/edit
5. 回读 commit/detail 校验
```

好处：**对任何草稿都成立**，不管它有几个 SKU、什么类目、带多少服务模板。代价是每次改价要开一次编辑页（约 15 秒），后续可以缓存载荷优化。

### 2.4 落地到哪

## 三、库存：找到字段了，但草稿态不落库

### 3.1 字段是 `quantity_delta`，不是 `quantity`

编辑载荷的 SKU 结构里**只有 `quantity_delta`**，没有 `quantity`。这是"增量"语义。

### 3.2 两种写法都没能让草稿库存变化

| 试法 | 结果 |
|---|---|
| `quantity_delta = 50` | commit/detail 回 `quantity: 0` |
| `quantity_delta = 50` + `quantity = 50` | 仍是 `0` |

`action/edit` 返回成功，价格也照改，但 `commit/detail` 的 `sku[].quantity` 一直回 0。

### 3.3 判断

**草稿（`is_shop = 0`）阶段库存不回显、不落库**——库存挂在"商品"实体上，草稿只是 commit，还没生成可售商品。这也解释了为什么源商品（在售）列表能看到 `quantity: 1010`，而它的草稿副本是 0。

**真正该走的路**：库存对**已上架商品**改，走商品级接口。抓包时已经发现这几个入口：

```
/guide-api/mms/inventory/batch_edit/gray      批量改库存
/guide-api/mms/modifySkuByExcel/gray          表格批量改 SKU（含价格库存）
/vodka/v2/mms/inventory/alert/query           库存预警
```

下一步要抓的是「商品列表 → 批量改库存」那一次提交，它作用于在售商品，语义更直接。
