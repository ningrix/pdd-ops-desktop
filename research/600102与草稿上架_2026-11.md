## 一、复制失败的真凶：600102

你发来的日志里有完整答案：

```json
{"error_msg":"该商品已被新建过,请勿连续新建","error_code":600102,"success":false}
```

**这个商品（goods_id 1028820098943）之前被反复新建过** —— 是我在调试阶段用脚本对同一个商品连做了多次 `copyGoodsCommit`（探路、验证字段、跑 CLI），把这个商品的新建配额用掉了。

所以：

| | 结论 |
|---|---|
| 是店铺问题吗 | 不是 |
| 是商品太多吗 | 不是（另一家 1 个商品的店能成功，恰恰说明和数量无关） |
| 是什么 | 同一商品短时间内被多次"新建" |
| 怎么绕 | 换一个没复制过的商品；或等平台冷却 |

已做：错误码翻译成人话，不再只说「copyGoodsCommit 被平台拒绝」。

```
复制失败：这个商品之前已经复制过一次，平台限制不能连续新建。
          换一个商品试试，或等一段时间再复制。
平台错误码：600102　原文：该商品已被新建过,请勿连续新建
```

## 二、"显示复制成功，但店铺里没有新商品"

**因为复制出来的东西是草稿，不是上架商品。**

流程是这样的：

```
你的在售商品
   ↓ copyGoodsCommit
新草稿（is_shop = 0）  ← 只存在于「商品管理 → 草稿箱」
   ↓ commit/submit
在售商品（is_shop = 1）  ← 这才出现在店铺列表里
```

之前程序只做到第一步，界面上写「复制成功」，你自然会去店铺里找——找不到是正常的。

### 已加两个入口

**复制弹窗里多了个勾选：**

```
☑ 复制后顺便改价（会多花约 15 秒）
☐ 复制后直接提交上架（不勾 = 只进草稿箱）
   不勾的话，商品只会出现在商家后台的「商品管理 → 草稿箱」，
   不会立刻出现在店铺在售列表里。
```

**结果卡片上多了个按钮：**

```
草稿已创建  未上架
  标题      测试商品-羽绒服-新款
  图片/SKU  20 张 / 60 个
  拼单价    292.22
  草稿号    206419698216
  提醒      库存为 0，上架前需补

  [ 提交上架到店铺 ]
```

勾了「直接提交上架」或者事后点这个按钮，商品才会进在售列表（还要过平台审核）。

## 三、必须说清楚的一个边界：**目前只支持「同店复制」**

你说"我从店铺2复制到店铺1"，但实际执行的时候，当前选中的是「店铺1」，所以程序做的是：

```
店铺1 的在售商品 → 店铺1 的草稿
```

**不是** 店铺2 → 店铺1。

原因：`copyGoodsCommit` 的 `source_goods_id` 必须在**发起请求的那家店的权限范围内**。店铺1 的登录态拿不到店铺2 的商品，所以跨店复制不能靠一次接口调用完成。

正确的跨店复制要两个阶段：

```
阶段 1（在店铺2 的 session 里）
  读取店铺2 商品 → 落成本地"商品数据包"
  （标题 / 主图 / 详情 / SKU / 规格 / 属性 / 运费模板）

阶段 2（在店铺1 的 session 里）
  用数据包新建商品 → 提交上架
```

阶段 2 目前没有现成接口可用——`copyGoodsCommit` 只能克隆本店商品，跨店必须走「新建商品」那条链（`action/edit` 从零构造，或走发布页表单）。这是下一步的主要工作量。

**所以现在的用法是**：只处理"同一家店内部，把 A 商品复制成 A 商品的新链接"这个场景。

按优先级：
