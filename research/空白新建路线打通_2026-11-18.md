## 二、真实流程（实测走通）

```
① /goods/category   ← 空白发布入口（从商品列表侧栏「发布新商品」的 href 拿到）
   ├─ 上传商品主图（1~10 张，1:1 或 3:4，>480px，<3M）
   ├─ 填商品标题（≤60 字符）

② 自动跳到 goods_add/index?type=add&from=category&version=predictCate&id=XXX&goods_id=YYY
   ├─ 平台根据图片+标题**自动预测类目** → 实测识别为「女装/女士精品 > 羽绒服 > 羽绒服」
   └─ 同时创建了真实草稿（拿到 id 和 goods_id）

③ 完整表单（和编辑页同一套组件）
   ├─ 商品轮播图：已上传 3/10 ✓
   ├─ 商品属性：平台已自动匹配「相似品属性」，可一键复用
   ├─ 商品规格：颜色分类 + 尺码（标准码制 7 种 + 「自定义尺码」输入框）
   ├─ 价格及库存
   └─ 保存草稿 / 提交并上架
```

## 三、关键技术突破：图片上传

空白新建必须先上传主图。而**页面的 JS 不可能给 `<input type="file">` 赋值**（安全限制），
这是过去所有"自动发布"方案卡住的地方。

**解法：CDP 的 `DOM.setFileInputFiles`**

```js
await dbg.sendCommand('DOM.enable');
const doc = await dbg.sendCommand('DOM.getDocument', { depth: -1, pierce: true });
const q = await dbg.sendCommand('DOM.querySelector',
  { nodeId: doc.root.nodeId, selector: 'input[type=file]' });
await dbg.sendCommand('DOM.setFileInputFiles',
  { nodeId: q.nodeId, files: ['C:\\...\\src_01.jpg', ...] });
```

浏览器随后按**正常流程**上传（不是伪造请求，平台看不出区别）。

### 实测结果

```
下载源图 3 张 → 本地 ok
setFileInput → {"ok": true, "count": 3, "files": ["src_01.jpg","src_02.jpg","src_03.jpg"]}
页面显示：上传图片 (3/10)   ← 成功
```

因为源图本来就在 PDD CDN（`img.pddpic.com`），我们先下载到本地再喂进去，
不涉及跨域、不涉及图床问题。

## 四、新增的能力（已提交）

| 接口 | 作用 |
|---|---|
| `main.js` `setFileInputFiles()` | 用 CDP 把本地文件塞进 file input |
| IPC `img:fetchToLocal` | 下载图片 URL 到本地目录（空白新建前置） |
| IPC `img:setFileInput` | 把本地文件喂给页面 file input |
| IPC `debug:eval` | **在当前店铺视图的主 frame 执行任意 JS** |

### `debug:eval` 为什么重要

外部 CDP 的 `Runtime.evaluate` 有时会落到**和 `executeJavaScript` 不同的执行上下文**
（拼多多页面里有 iframe），会导致"以为看到的内容"和"生产代码看到的内容"不一致 ——
排查时会得出完全错误的结论。

`debug:eval` 走的是与 `runInMall` **完全相同**的 `executeJavaScript` 通道，保证上下文一致。
这一轮所有可靠结论都是用它的。

## 五、还有一个小尾巴：自定义尺码的提交方式

尺码区实测有两个输入框：

```
{ type: "text", placeholder: "未使用模板" }      ← 尺码表模板选择器
{ type: "text", placeholder: "自定义尺码" }      ← 自定义尺码输入
```

我把 `2（90-100）` 这类值逐个输入 + 派发 Enter，**没有生成对应的复选框**。
说明它不是"输入即添加"，还需要某个触发动作（可能要点旁边的添加按钮，或这是一个
组合输入行需要失焦提交）。

这个细节还没验证完。但**这不影响路线可行性** —— 输入框存在，只是交互方式要再摸一次。

## 六、对比两条路线

| | 骨架克隆（现方案） | **空白新建（新方案）** |
|---|---|---|
| 依赖目标店有同品类商品 | ❌ 强依赖 | ✅ 完全不依赖 |
| 600102 频控 | ❌ 会撞 | ✅ 没有 |
| 尺码 | 受骨架码表限制 | ✅ 可自定义 |
| 类目 | 继承骨架 | ✅ 平台自动识别 |
| 图片 | 直接改 URL（简单） | 要下载再上传（多一步，但已解决） |
| 商品属性 | 继承骨架 | 需自己填（但平台能给"相似品属性"一键复用） |
| 速度 | 快（约 30 秒） | 慢一些（上传图 + 填属性） |
| 抗平台变动 | 依赖 copyGoodsCommit | 依赖发布页 DOM（页面改版就要跟） |

**建议：空白新建作为主路径，骨架克隆保留为快路径。**

因为空白新建没有频控、没有品类依赖，能真正批量跑；骨架克隆适合"目标店已有同品类、要求快"的场景。
