## 一、官方文档：拼多多确实给了「完全不用浏览器」的正路

拼多多开放平台（`open.pinduoduo.com`）提供商品发布 API，网关是 `gw-api.pinduoduo.com/api/router`，`type=pdd.goods.add`。

**完整调用链**（8 步）：

```
pdd.goods.authorization.cats    → 商家可发布类目
pdd.goods.cats.get              → 逐级下钻叶子类目 ID
pdd.goods.image.upload          → 上传商品图
pdd.goods.cat.rule.get          → 类目属性/标品/规格规则
pdd.goods.spec.get              → 规格 ID
pdd.goods.spec.id.get           → 生成自定义规格 ID（颜色等）
pdd.goods.add                   → 商品新增（直接发布）
pdd.goods.commit.status.get     → 审核状态
（草稿路径：pdd.goods.edit.goods.commit → pdd.goods.submit.goods.commit）
```

**参数结构**（社区里有人贴出了完整实测）：

```
type=pdd.goods.add & data_type=JSON & timestamp=… & client_id=… & access_token=…
& cat_id=叶子类目ID & carousel_gallery=主图组 & detail_gallery=详情组
& goods_name=标题 & goods_desc=描述 & market_price=市场价 & cost_template_id=运费模板
& sku_list=SKU组 & is_refundable=true & shipment_limit_second=承诺发货时间 & sign=签名
```

**这条路的问题不是技术，是资质**：
- 必须注册为 ISV，「商家后台系统」类目**仅支持企业资质**（营业执照 + 公司门头视频 + MRD/PRD 文档）
- 需通过应用审核 → 申请「商品发布权限包」
- 敏感接口强制云内部署：云主机约 2460/年 + 云数据库约 2211/年 + OSS/EGW 约 150/年 ≈ **4800 元/年**
- 服务市场按结算收入 0.6% 交技术服务费

**⚠️ 一个必须提醒的坑**：网上不少「拼多多 API 教程」把 `pdd.logistics.online.send` 当商品创建 API —— 那是**订单发货**接口，不是发品。跟着抄会浪费一整天。发品只有 `pdd.goods.add`。

结论：**官方 API 是最稳的，但门槛把你挡在外面（企业 ISV + 权限包 + 云部署）。** 你要自用、团队用、3 个店，走这条不划算。

## 二、GitHub 上的现成项目（都验证过真实存在）

### 1. `zhaoyta/pddbot` —— 最值得参考的工程样板

[github.com/zhaoyta/pddbot](https://github.com/zhaoyta/pddbot)

- 技术栈：**Playwright + LangGraph + PySide6 GUI**
- 目标站点：`mms.pinduoduo.com/chat-merchant`（商家工作台客服）
- 一键启动：`start.bat` 自动检查 uv → 建 venv → `uv pip install -r requirements.txt` → `playwright install chromium` → 启动 GUI
- **它的价值**：证明了三件事——① Playwright 能稳定驱动 `mms.pinduoduo.com`；② 打包成双击即用的桌面程序是可行的；③ 用本地浏览器 profile 复用登录态是标准做法

这个项目的启动器设计（uv 自举、虚拟环境、浏览器内核安装、GUI 包一层）可以直接抄给你团队用。

### 2. `81211860/ecommerce-agent-browser-skill` —— 最对口

[github.com/81211860/ecommerce-agent-browser-skill](https://github.com/81211860/ecommerce-agent-browser-skill)

- 定位：「通用电商浏览器自动化底座」，**从 PDD Agent 项目抽取而来，拼多多商家后台是第一个已验证的垂直场景**
- 设计思路值得抄：不把平台操作写死成脚本，而是给 Agent 一套「稳定、可观察、可执行、可复盘」的浏览器底座——页面信息、可点击目标、动作反馈、截图证据、网络请求、经验库
- 它明确说这是「Claude Code 的电商套壳」，降低小白使用门槛

**这是市面上和你需求最接近的项目**，建议通读它的 README 和 recipe 设计。

### 3. `yinnho/aginxbrowser` —— 底层通道的答案

我前面用的 `copyGoodsCommit` 路径就来自这里。它证明的是：**不用 Playwright 点 DOM，直接调后台自己的 XHR，更快更稳**。

### 4. `fengrunda/pdd-ai-tool` —— 官方 API 路线的参考实现

走开放平台 API 的 CLI：百炼生图 + 文案生成 + `pdd.goods.add` 发草稿 + 智能 SKU 定价。适合你将来真拿到 ISV 资质时参考。

### 5. DrissionPage 生态 —— 国内的隐藏主流

多篇做拼多多店群 RPA 的架构文章都在用 **DrissionPage** 而不是 Selenium/Playwright，原因：它能**接管你已经打开的 Chrome**（`ChromiumPage(addr_or_opts='127.0.0.1:9222')`），不用重登，也不加 Selenium 那种明显的自动化特征。

## 三、四种方案对比

| 方案 | 要手动吗 | 安装依赖 | 登录态复用 | 自动化指纹 | 适合谁 |
|---|---|---|---|---|---|
| **A. 开放平台 API** | 完全不用浏览器 | 企业 ISV + 权限包 + 4800/年 | 不需要 | 无（官方） | 有企业资质、追求正规 |
| **B. Playwright 启动新浏览器** | 每次要扫码（除非持久化 profile） | `pip install playwright` + 150MB 内核 | 可持久化 | ⚠️ 默认带 `--enable-automation` | 团队桌面工具（pddbot 路线） |
| **C. Chrome MV3 扩展** | 装一次，永久自动 | 无（浏览器原生） | 天然复用 | 无 | 团队分发最省心 |
| **D. CDP 直连（我选的）** | 登录一次，永久自动 | 无（Python 已有 websocket） | ✅ 复用 | ✅ 无（直接起 chrome.exe，不加自动化 flag） | 自用 + 内部工具 |

## 四、我选了 D（CDP 直连），而且已经跑通

### 为什么是它

1. **零安装**：你机器上 `websocket-client 1.9.2` 已经有了，不用 pip 装 playwright、不用下 150MB 浏览器内核
2. **没有自动化指纹**：直接启动 `chrome.exe`，不加 `--enable-automation`，也不重写 `navigator.webdriver` —— 比 Playwright 默认启动干净
3. **复用登录态**：同一个 profile，登录一次永久有效
4. **不需要改页面 DOM**：直接执行后台自己的 `__mms.fetch.sync`，跟你在 Console 里粘贴完全等价，但由脚本代劳

### 已经验证的部分

```
[OK] CDP 端口就绪: Chrome/157.0.8103.78
[..] 当前页面数: 1
[!] 命中登录页: https://mms.pinduoduo.com/login/?redirectUrl=…
    → 请在这个工作浏览器窗口里扫码登录
=== 返回值 ===
{ "ok": false, "host": "mms.pinduoduo.com",
  "error": "__mms.fetch.sync 不可用（页面不是 MMS shell，或还没加载完）" }
```

**链路是通的**：端口起来了、页面命中了、JS 执行了、结构化结果回传了。只差登录这一步——这是唯一一次人工操作。

### Chrome 136+ 的硬约束（重要）

Chrome 从 136 起**禁止默认 profile 带 `--remote-debugging-port`**（安全修复）。所以必须用独立的 `--user-data-dir`。

这反而是好事：
- 工作浏览器和你的日常浏览完全隔离，互不影响
- 团队每人一个独立 profile，天然做到「设备隔离」（平台关联识别看的就是设备维度）
- 代价只是**一次性登录**

## 五、你要做的两步（之后永久自动）

**第 1 步：双击启动**

```
tools\启动拼多多工作浏览器.bat
```

它会：起工作浏览器（独立 profile + 9222 端口）→ 打开 `mms.pinduoduo.com/home/` → 自动跑一次读取 → 打印结果。

**第 2 步：在弹出的窗口里扫一次码**

之后所有自动化都连这个实例。再也不用 F12、不用粘贴。

日常用法就一条命令：

```powershell
python tools\cdp_eval.py work\pdd_list_result.js
```

## 七、下一步路线

登录完成后，我按这个顺序推：

1. **确认商品列表和字段结构** → 定 `commit_id` 从哪拿、价格字段真名
2. **跑一次真复制**（`copyGoodsCommit` → 草稿）→ 验证端到端
3. **把 CDP 脚本升级成常驻服务**：Python 起个本地 HTTP 服务，前端页面点按钮 → 后端用 CDP 执行 → 团队都能用
4. **上团队版骨架**：账号权限 + 商品库 + 任务队列 + 回读校验

到第 3 步，就完全不是你手动跑了，是**点一下按钮**。
