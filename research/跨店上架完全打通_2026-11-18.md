## 二、最后两个坑是什么

### 坑 1：继承的尺码表会「过期」

```
报错：10000014 尺码表参数或组别不能为空
```

我一开始以为是"缺少尺码表"，准备去建。但查源商品发现：

```
源商品 界山XTG 的 size_spec_id = 空
而它能在售
→ 这个类目（登山鞋 11985）根本不要求尺码表
```

真正的因果：**骨架继承了一张旧尺码表**（`size_spec_id=354981836`），
我把尺码集合改掉后，那张表内部记录的码值和新的 SKU 集合对不上，
平台就报"参数为空"（措辞有误导性）。

**解法：源商品没有尺码表 → 把继承来的置 0。**

```js
body.size_spec_id = 0;
body.size_parent_spec_id = 0;
body.is_size_spec_sync_detail = 0;
```

实测一次通过。**不需要建尺码表，只要清掉脏的。**

### 坑 2：参考价必须严格大于单买价

```
报错：1000161 规格单买价格必须小于参考价格
```

我之前把 `market_price` 设成 `源拼单价 + 100`，但单买价也是 `源拼单价 + 100`，
两者相等 → 被拒。

**解法：参考价 = max(所有 SKU 单买价) + 100。**

```js
const maxSingle = Math.max(...body.skus.map(s => s.price));
body.market_price = Math.max(maxSingle + 100, 源拼单价 + 200, 原参考价);
```

## 三、完整链路（现在的真相）

```
① 采集源商品 → 采集箱（含颜色/尺码/SKU/图/价格/尺码表引用）
② 切到目标店
③ 找【同品类】骨架商品（不同品类直接拒绝，不产废品）
④ 克隆骨架 → 草稿
⑤ 打开发货草稿编辑页
⑥ 滚动到「规格与库存」等懒渲染（不滚就不存在！）
⑦ DOM 改颜色（原生 setter + input 事件，页面自动加行）
⑧ DOM 勾尺码（从 SKU 表格反推已生效码，用差集点标签）
⑨ 点页面「保存草稿」← 关键：让页面自己生成合法 spec_id
⑩ 抓最终载荷 → 覆盖标题/主图/价格/库存 → 清空继承的尺码表
⑪ 保存 → 提交
```

### 为什么必须是这个顺序

| 步骤 | 不可替代的原因 |
|---|---|
| ⑦⑧ DOM 改规格 | `action/edit` 会**静默丢弃** spec 变更（返回 ok 但重载后不变） |
| ⑨ 页面保存 | 只有页面自己会为新规格生成 `spec_id`（平台按商品分配的） |
| ⑩ 清尺码表 | 骨架的表记的是旧码值，改码后必然冲突 |
