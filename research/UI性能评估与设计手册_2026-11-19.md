# UI 性能评估与设计手册

> 2026-11-19 ｜ 对应应用：拼多多上货中台（Electron 40.10.2）
> 测量环境：真实 Electron renderer，CDP `127.0.0.1:9333`，软件渲染（`app.disableHardwareAcceleration()` + `--disable-gpu`）

## 一、结论摘要

当前 UI 属于**轻量原生渲染层**：无 React/Vue，无构建步骤，单页 DOM 规模小。实测结果：

| 指标 | 实测值 | 评价 |
|---|---:|---|
| DOM 元素数 | 623–632（两次采样） | 很低，远低于需要虚拟化的规模 |
| DOM 节点总数（含文本节点） | 1490–1506 | 低 |
| 事件监听器 | 102 | 低到中等，主要是列表行按钮 |
| CSS 规则数 | 392 | 低 |
| 首次 DOMContentLoaded | 277–286ms | 可接受 |
| loadEvent | 278–287ms | 可接受 |
| 空闲 JS Heap | 3.19–3.24MB | 很低 |
| 交互后 JS Heap | 3.34MB（+102KB） | 无明显泄漏迹象 |
| 主题切换 | 13.4–32.3ms（含两次 rAF 基线约 33ms） | 实际切换即时，无长任务 |
| 页签切换 | 23.9–55.7ms（含 rAF 基线） | 可接受；采集箱首次渲染略重 |
| 采集箱渲染 | 34.1–35.4ms / 13 行 | 可接受；超过 100 行需虚拟化 |
| 长任务（longtask） | 0 | 未观察到 >50ms 长任务 |
| 侧栏 | `clientHeight=637 = scrollHeight=637` | 无滚动条，符合“单页展示” |

总体结论：**当前 UI 性能良好，主要风险来自软件渲染下的大面积动画、列表规模增长和每行独立事件监听**，而不是 DOM 数量或 JS 执行。

## 二、测量方法

1. 用 `tools/restart-app.ps1` 正常重启，确保主进程加载最新 `main.js`。
2. CDP 连接 `renderer/index.html` 页面，启用 `Performance` domain。
3. 采集：
   - `Performance.getMetrics()`：Task/Script/Layout/RecalcStyle/JSHeapUsedSize/Nodes
   - `Memory.getDOMCounters()`：documents/nodes/jsEventListeners
   - `document.querySelectorAll('*').length`
   - `PerformanceObserver({ entryTypes: ['longtask'] })`
   - 以 `requestAnimationFrame` 双帧作为交互结束点测量主题/页签/采集箱渲染
4. 测量源码规模：
   - `app.js`: 64KB / 1564 行
   - `style.css`: 36KB / 714 行
   - `index.html`: 22KB
5. 可重复执行：`python tools/ui_perf_check.py --strict`（输出 JSON 并检查性能预算）。

> 说明：Electron 在软件渲染下，`requestAnimationFrame` 本身有约 16.7ms/帧的调度基线；表中“主题/页签耗时”包含约两次 rAF 的等待，不代表纯 JS 耗时。

## 三、性能分析

### 3.1 好的部分

- **DOM 规模小**：623 个元素，远低于复杂后台页面常见 3000+ 的规模。
- **CSS 规则少**：392 条，选择器层级浅；主题只用 CSS 变量，切换成本低。
- **无框架运行时**：没有虚拟 DOM diff、没有 hydration、没有第三方 UI 包。
- **主题切换不再做整页动画**：当前点击即时切换，只在按钮内部做小圆圈扩散；无 View Transitions 的快照开销，无白屏遮罩。
- **窗口按钮改为自绘**：不再依赖 `titleBarOverlay`，避免 Windows/DPI 下原生按钮区与 CSS 顶栏 2~3 物理像素的错位。
- **侧栏无滚动条**：`clientHeight=scrollHeight=637`，内容在一屏内。
- **长任务 0**：主题切换和常规页签切换未产生 >50ms 长任务。

### 3.2 需要关注的瓶颈

1. **采集箱首次渲染 35.4ms（13 行）**
   - 当前 `refreshPool()` 用 `innerHTML` 拼行，然后每行用 `querySelector` 绑定 4 个按钮的独立监听器。
   - 13 行时无感；若采集箱增长到 100+ 行，监听器数量和 DOM 更新会线性增长。
   - 建议：`DocumentFragment` 一次构建 + 事件委托（`#poolBody` 上监听 `data-act`），行数超过 100 时做虚拟列表或分页。

2. **页签切换 55.7ms（采集箱首次）**
   - 其中约 33ms 是 double-rAF 基线，纯渲染约 20ms；仍是页签中最高的。
   - 主要成本是 13 行 × 缩略图/按钮 + 重新布局。
   - 建议：缩略图加 `loading="lazy"` + `decoding="async"`；表格行数增长时启用虚拟化。

3. **每行 4 个按钮 = 每行 4 个监听器**
   - 当前 13 行约 52 个监听器；100 行约 400 个。
   - 事件委托是低风险、收益明确的优化。

4. **图片缩略图**
   - 采集箱表格直接使用远程 `thumb`，没有 `loading=lazy`/固定尺寸占位。
   - 图片 CDN 慢时会影响首屏行布局；建议 `width/height` 固定 + `object-fit` + lazy。

5. **店铺状态轮询**
   - `refreshStatus()` 每 25 秒对所有店铺并发 `pingMall`；店铺数量多时会产生集中请求。
   - 当前 2 店无感；建议 10 店以上按店铺错峰（`setTimeout` 随机 0~2s）或分批。

6. **软件渲染是硬约束**
   - `app.disableHardwareAcceleration()` 是当前环境要求，不能按“普通浏览器”的性能假设设计。
   - 大面积 `filter`/`backdrop-filter`/`box-shadow`、整页 `clip-path` 动画、View Transitions 双快照，在软件渲染下都会明显掉帧。
   - UI 动画只使用**小面积 transform/opacity**，或者即时切换。

## 四、性能预算（建议纳入验收）

| 项目 | 预算 | 测量方式 |
|---|---:|---|

## 五、未来 UI 设计手册

### 5.1 技术与平台前提

1. **技术栈保持 Electron 40 + 原生 HTML/CSS/JS**
   - 不引入 React/Vue/构建步骤；不引入需要原生编译的依赖。
   - 文件仍用 `file://` 加载，**禁止 `type="module"` / `import` / `export`**，否则静默白屏。
2. **软件渲染优先**
   - 不使用 `backdrop-filter`、大面积 `filter`、`box-shadow` 扩散、整页 View Transitions。
   - 动画只动 `transform` / `opacity`，且面积尽量小。
3. **WebContentsView 区域是“禁区”**
   - `#pane-browser` 的祖先不得使用 `transform` / `filter` / `perspective` / `will-change` / `contain:paint` / `backdrop-filter`。
   - 任何浮层不得覆盖 `#pane-browser` 矩形；日志/结果抽屉固定在左侧栏宽度内。
4. **窗口标题栏**
   - `titleBarStyle: 'hidden'`，**不使用 `titleBarOverlay`**。
   - 顶栏 40px，自绘 `.win-controls`（最小化/最大化/关闭），通过 `window:action` IPC 控制。
   - 顶栏可拖拽，所有可点元素 `-webkit-app-region: no-drag`。

### 5.2 布局原则（按 iOS/macOS 侧边栏思路）

1. **主导航固定在左侧**
   - 商品列表 / 采集箱 / 采集会话 / 资金复盘 / 店铺后台，顺序按使用频率。
   - 激活态用细蓝色左边线，不用胶囊底色；页面不出现第二套顶部页签。
2. **一个功能只有一个入口**
   - 「店铺后台」就是浏览器的唯一入口，不再放「显示浏览器」开关。
   - 在线状态用店铺指示灯表达，不再放「检测登录」按钮。
3. **顶栏保持安静**
   - 只保留品牌、刷新页面、深色/浅色、自绘窗口按钮。
   - 不在顶栏堆业务按钮；业务操作放左栏或页面内。
4. **左栏 248px，禁止滚动条**
   - 所有左栏内容必须在一屏内；新增内容先考虑移入页面或次级面板，不靠滚动解决。
   - 分区是普通标题 + 内容，不做胶囊折叠。
5. **紧凑数据表**
   - 缩略图 30px、行距 4px、操作按钮单行；表格字体 11.8px，表头 10.8px。
   - 目标：一屏 ≥ 12 条商品。

### 5.3 视觉与主题

1. **两套主题，一套变量**
   - 所有颜色走 `:root` / `html[data-theme="light"]` 的 CSS 变量；新增颜色必须先加变量。
2. **图标状态唯一**
   - 深色模式只显示月亮，浅色模式只显示太阳；不把两个图标叠在一起。
   - 图标显示/隐藏规则必须用足够高的选择器优先级，避免被 `.btn svg { display:block }` 一类规则覆盖。
3. **主题切换即时**
   - 不做整页颜色过渡、不做全屏遮罩；只在主题按钮内做局部小圆圈扩散。
4. **焦点环**
   - 按钮和页签不显示系统金色 `focus-visible` 环；需要键盘焦点时使用自定义蓝色细线（不要用金色）。
5. **字体/尺寸基线**
   - 顶栏 40px；侧栏 248px；正文 12px/12.5px；表格 11.8px；按钮最小高度 28px。

### 5.4 列表与交互性能规范

1. **列表构建**
   - 超过 30 行使用 `DocumentFragment`；超过 100 行使用虚拟列表/分页。
   - 行内按钮用事件委托，禁止每行绑定多个闭包监听器。
2. **图片**
   - 表格缩略图必须设置固定 `width/height`、`loading="lazy"`、`decoding="async"`，避免图片加载导致布局跳动。
3. **状态轮询**
   - 每 25 秒刷新一次状态可以保留；10 店以上需要错峰。
   - 已知状态刷新时保持原色，不闪 amber；`checking` 只在未知状态使用。
4. **DOM 读写分离**
   - 先读 `getBoundingClientRect`，再批量写样式；禁止在循环中反复触发布局。
5. **动画**
   - 任何动画先问：是否大面积？是否软件渲染？如果答案是大面积或整页，直接改为即时切换。
   - 可接受的：按钮内部小圆圈、icon rotate、单行 hover。

### 5.5 交互文案

1. 价格/加价类输入必须写清公式：
   - 「原价 × [1] 倍　1 = 不加价」
   - 不使用「加价 1 倍」这种有歧义的说法。
2. 状态类文案：
   - 在线指示灯 `st on` / `off` / `unknown`；不重复写「检测登录」。
3. 失败/未知状态：
   - 状态未知只显示「待确认」，不自动重试或自动提交。

### 5.6 验收清单（每次 UI 改动必须执行）

1. `node --check app/renderer/app.js`、`node --check app/main.js`、`node --check app/preload.js`
2. `node tools/check-injections.js` 必须 PASS
3. 主进程/预加载改动后必须重启：
   - `powershell -ExecutionPolicy Bypass -File tools/restart-app.ps1`
   - 检查 `Get-Process electron` 的 `StartTime` 晚于 `app/main.js` 的 `LastWriteTime`
4. CDP 性能：
   - `document.querySelectorAll('*').length ≤ 1200`
   - `document.styleSheets[0].cssRules.length ≤ 600`
   - `PerformanceObserver('longtask')` 无 >50ms
5. 全窗口像素检查：
   - 顶栏底部在左、中、右、最右侧窗口按钮区的 y 值完全一致
   - 不允许出现原生 `titleBarOverlay` 多出来的深色块
6. 侧栏：
   - `scrollHeight == clientHeight`
   - 无滚动条、无胶囊、无“快捷操作/检测登录”
7. 主题：
   - dark: moon=block, sun=none
   - light: moon=none, sun=block
8. 店铺状态：
   - 在线店铺 `st on`，离线 `st off`；cashier 页面也能正确识别（`ops.ping()` 已兼容）
9. 日志/原始结果：
   - 抽屉可打开；`#log` / `#resultBox` 仍在 DOM；agent 可直接读取
10. 实际 Electron 截图，不接受只给浏览器预览

## 六、后续优化建议（按投入产出排序）

| 优先级 | 改动 | 收益 |
|---|---|---|
| P0 | 采集箱行按钮改事件委托 + DocumentFragment | 降低行数增长时的监听器/重排成本 |
| P1 | 缩略图 lazy + 固定尺寸 | 减少图片加载造成的布局抖动 |
| P1 | 采集箱 >100 行虚拟列表 | 防止大数据量卡顿 |
| P2 | 店铺状态 10 店以上错峰轮询 | 降低集中 IPC/网络压力 |
| P2 | 日志/结果抽屉内容虚拟化 | 500 条日志时保持滚动流畅 |
| P3 | `tools/ui_perf_check.py` 纳入每次 UI 改动验收 | 防止性能回退（已提供） |
