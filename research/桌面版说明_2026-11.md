## 二、为什么选 Electron + WebContentsView

| 方案 | 内置浏览器 | 多店铺隔离 | 登录态持久 | 指纹干净 | 结论 |
|---|---|---|---|---|---|
| 本地网页 + 外部 Chrome + CDP | ❌ 要另开窗口 | 靠多个 profile 目录 | ✅ | ✅ | 能用，但正是你不想要的形态 |
| **Electron + WebContentsView** | ✅ 真嵌入 | ✅ `persist:partition` 原生隔离 | ✅ | ✅ 可去 UA 里的 Electron 标识 | **选它** |
| PySide6 + QWebEngine | ✅ | 需自己管 cookie 目录 | ◐ | ◐ QtWebEngine 指纹偏门 | 备选 |
| Tauri + WebView2 | ✅ | 需自己管 | ◐ | ◐ WebView2 指纹偏门 | 备选 |

**关键收益：多店铺登录隔离是白送的。**

每个店铺一个 `session.fromPartition('persist:mall_xxx')`，等于每个店铺一套独立 cookie / localStorage / IndexedDB。三个店同时在线，互不串号；重启应用后登录态还在（见下面那个已修的 bug）。这正是竞品「窗口化多开」的本质，但比开一堆 Chrome 干净得多——不用管端口、不用管 user-data-dir、不用管哪个窗口对应哪个店。

## 三、怎么用

### 启动

```
双击 app\启动.bat
```

首次会自动 `npm install`（走 npmmirror 镜像）。

### 加店铺

1. 点左侧 **＋ 添加**
2. 输入名字（例：`A店-羽绒服`）
3. 右边内置浏览器会打开拼多多商家后台，**扫码登录一次**
4. 登录后点顶部 **检测登录**，看到「登录有效」就成了

再点 ＋ 添加 加第二个店 → 它用另一套 session，互不影响。

### 干活

1. **读取在售商品** → 切到「商品列表」看表格（拼单价/单买价/SKU数/库存/goods_id）
2. 填「复制第几条」和「新标题」→ **复制成草稿**
3. 「执行结果」里会打出完整链路和新建的 `commit_id` / `goods_id`
4. 到后台草稿箱肉眼确认

底部的日志会实时打出每一步：

## 四、跑起来踩的三个坑（都解决了，记下来免得再踩）

### 坑 1：`ELECTRON_RUN_AS_NODE=1`

这台机器的环境变量里有 `ELECTRON_RUN_AS_NODE=1`。后果是 **electron.exe 会退化成纯 Node 运行**，`require('electron')` 返回一个字符串，`ipcMain` 是 `undefined`，界面永远起不来。

症状：`electron.exe --version` 打印的是 `v20.18.3`（Node 版本）而不是 Electron 版本。

已解决：`启动.bat` 里 `set "ELECTRON_RUN_AS_NODE="`。

⚠️ 注意 `set VAR= && cmd` 这种写法会把它设成**一个空格**（仍算已设置），必须用 `set "VAR="` 的引号形式。

### 坑 2：Electron 33 在这个环境原生崩溃

`0xc0000005` 访问违例，偏移固定在 `electron.exe` 内部，`--version` 能跑但一建窗口就崩。

已解决：换 **Electron 40.10.2**（39.8.10 也正常）。33 的包本身是完整的，纯粹是和这个环境不兼容。

### 坑 3：必须加 `--no-sandbox --disable-gpu`

不加的话 Chromium 沙箱初始化失败，同样直接崩。已在 `启动.bat` 里固定带上，`main.js` 里也补了 `app.commandLine.appendSwitch('no-sandbox')` 和 `app.disableHardwareAcceleration()` 兜底。

### 顺带修的一个真 bug

原来每次启动都给店铺重新生成 `id`，而 `partition = 'persist:' + id` —— 意味着**重启一次登录态就没了**。现在 id 写进 `malls.json`，重启复用同一个 partition，登录态持久。

## 五、代码结构

```
app/
├─ 启动.bat                  启动器（清环境变量 + 带 flag + 首次自动装依赖）
├─ package.json              electron 40.10.2
├─ main.js                   主进程：窗口、店铺视图池、IPC、启动恢复
├─ preload.js                contextBridge 暴露 window.pdd（不开放 node）
├─ lib/
│  └─ ops.js                 注入到 PDD 页面执行的业务 JS（已验证的 API 链）
└─ renderer/
   ├─ index.html             面板结构
   ├─ style.css              深色主题
   └─ app.js                 前端逻辑 + BrowserView 区域跟随布局
```

### 核心机制：内置浏览器怎么"贴"在界面上

`WebContentsView` 不是 DOM 元素，没法用 CSS 定位。做法是前端算出占位 `<div>` 的屏幕矩形，通过 IPC 报给主进程，主进程再 `view.setBounds()`：

```js
// renderer/app.js
const r = $('#pane-browser').getBoundingClientRect();
window.pdd.setBounds({ x: r.left, y: r.top, width: r.width, height: r.height });
```

切 tab、改窗口大小、收起浏览器，都会重新同步。切走时 `removeChildView` 把视图摘掉，回来再挂上——**登录态不受影响**，因为 session 是独立的。

### 业务层没变

`lib/ops.js` 里就是前面实测跑通的那条链：

```
create_by_sn → copyGoodsCommit → update_goods_commit_info → commit/detail → (submit)
```

只是执行方式从「CDP 端口 + Runtime.evaluate」换成了 `view.webContents.executeJavaScript()`——同一个 JS，少了一层网络和端口。
