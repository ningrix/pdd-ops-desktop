# UI 方向调研（拼多多上货中台）

> 2026-11-21 ｜ 结论先行：**维持 vanilla 无构建栈，borrow token 体系不引框架**；UI 方向按四个学术/工程视角重推，产出四个可落地样张。
> 调研方式：WebSearch（同类项目 + 设计体系）+ MCP（context7 查 TDesign token 文档、deepwiki 试图查 GitHub 项目）+ WebFetch（GitHub README、Apple HIG）。
> 硬约束回顾：无构建步骤、file:// 加载禁 ES module、不引原生编译依赖、软件渲染（无 GPU）、离线可用。

## 一、技术栈结论

**维持 vanilla CSS + 双层 CSS 自定义属性 token，不引入框架/组件库。**

| 选项 | 判定 | 理由 |
| --- | --- | --- |
| Vue3 + Vite + TDesign（同类项目的主流栈） | ❌ | 本项目渲染层由 `loadFile()` 以 file:// 加载，ES module 被 CORS 静默阻断（AGENTS §1.1）；构建产物即 module → 需要改加载模型 + 引入构建链，违反两条硬约束 |
| Lit / Web Components | ❌ | 同样依赖 ESM |
| 运行时 CDN 引入组件库 | ❌ | 离线不可用 + 向拼多多域名外发请求增加指纹面 |
| **vanilla + token 化（采纳）** | ✅ | 零依赖、零构建、可断言；设计质量来自 token 纪律而非组件库 |

**Token 架构借鉴对象**：TDesign 的两层式 CSS 变量（全局 `--td-brand-color` + 组件级 `--td-button-*`，见 context7 抓取的官方 custom-theme 文档）→ 本项目对应 `--u-*` 全局层 + 组件层；Ant Design 的 [For Agents design.md + 官方 MCP](https://ant.design/docs/react/mcp)（`antd_token` 工具可查 token）记录为后续可选接入，用于校对 token 命名与对比度。

**未来若接受构建步骤**：TDesign Vue Next 是同生态首选（腾讯系、B 端、暗色 token 完整、Vue Next Starter 脚手架）。迁移成本 = 加载模型改造 + 构建链 + 全量回归，不在本轮讨论。

## 三、设计体系与观念依据

### 3.1 苹果 HIG（macOS）
- **Clarity / Deference / Depth** 三原则：界面在每个字号下可读、chrome 最小化让内容优先、层级靠层次而非装饰。
- macOS 落点：边栏即导航（deference 的载体）、窗口内容优先、精确的系统字体。
- 应用到本项目：数字是主角 → 表格字号/对齐/tabular-nums 是第一优先级；边栏压暗压平；深度只用一层（面板色差 + 1px 线），不用阴影堆叠（软件渲染）。

### 3.2 社会心理学（前景理论 / 认知负荷）
- **损失厌恶**（Kahneman & Tversky 1979，损失痛感 ≈ 收益的 2 倍）：红色语义要留给真正的损失，且不能滥用——撒满屏小红字 = 焦虑放大器。
- **递减敏感性**：一次大损失比十次小损失痛感低 → **费用聚合呈现**（每单扣费 19.96 一个大数）优于逐笔罗列；行内的退款小字保持灰阶弱化而非红色。
- **参照点**：同一段现金流，框架是「较昨日/较上月」还是绝对值，决策不同 → 现金流卡保留参照信息位（日期/月份）。
- **Hick 定律**：选项越多决策越慢 → 顶部动作收敛为「采集全部店铺（主）+ 其余（次）」两级。
- **Doherty 阈值**（<400ms 反馈）：本地操作全部即时反馈，长任务（采集）必须有进度与预期时长——现行实现已满足。

### 3.3 政治经济学（平台-商户关系）
- **权力不对称**：平台规则（仅退款、8% 加价上限、600011 处罚态）单方面约束商户 → 工具的立场是「把平台拿走的算清楚」，费用条与技术服务费分类（CAT_MAP）是这一立场的产物，UI 上应保持费用可见性而不是藏进折叠。
- **信息不对称**：平台的费率/规则/判定（假货判定 20/22）只有平台掌握全貌 → 工具把判定结果原样带出（risk 页）并给行动提示，不做粉饰。
- **数据主权**：一切落盘在本地 JSON（AGENTS §6）→ UI 提供「导出」入口（样张顶栏新增），强化「数据是商户自己的」。
- **劳动过程**：个体劳动者的时间是唯一不可再生产资源 → 高密度方向（B）服务于「减少扫数时间」，自动化动作（批量、采集）保持人工确认门槛（AGENTS §1.2）不变。

## 四、四视角 → 设计决策映射

| 视角 | 决策 | 落在哪个方向 |
| --- | --- | --- |
| HIG deference | chrome 压平、数字加粗放大 | A |
| 政治经济学·信息不对称 | 账本式逐笔、等宽数字、零装饰 | B |
| 前景理论·参照点+聚合 | 末卡强调位、费用大数、chips 行动信号前置 | C |
| HIG clarity | 白底、AA 语义色（#0f7a4d/#c0392b/#96601a）、清晰边界 | D |
| 软件工程 | 四方向共用一套 DOM + 双层 token，换向 = 换变量；迁移路径 token→组件→状态→断言 | 全部 |
