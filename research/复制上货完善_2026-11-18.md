## 五、逐 SKU 价格映射

### 做法

按「规格组合」建索引，键 = `parent_name:spec_name` 拼接：

```js
const skuKey = (spec) => spec.map(x => x.parent_name + ':' + x.spec_name).join('|');
const srcMap = new Map();
for (const s of it.skus) srcMap.set(skuKey(s.spec), s);
// 目标 SKU 逐个查表，用源的 group/single 价，乘可配置倍数
```

### 实测

```
价格映射: 逐 SKU 80 个
最终 SKU 数: 80
提交: ok
```

回读验证：80 个 SKU 拼单价/单买价各只有 1 种。

**这是对的**——我查了源商品，它本身就是统一价：

```
源 SKU 数: 80
源拼单价种类: 1 [28966]
源单买价种类: 1 [29066]
```

映射逻辑执行了 80 次逐个查找，只是源没有差价可搬。**换成有差价的老链接，价格会跟着源走。**

界面上批量栏新增「加价 ×N 倍」输入，可对整批统一乘倍。

## 六、详情图：没做完，原因具体

### 尝试

1. 在采集时把 `decorationDetail`（详情装修楼层）存进采集箱
2. 上架时整体替换 `body.decorationDetail`

### 卡住的地方

```json
{"decorationDetail 条数": 0}
```

`collectGoods` 用的是 `commit/detail` 接口，**它不返回详情装修数据**。
详情装修是另一个接口（编辑页的「装修商详」模块单独加载）。

所以：**代码钩子写好了，但没有数据源。**

### 要补什么

抓一次编辑页「装修商详」的请求，找到读详情装修的接口，在采集时多调一次并存下来。
估计半天到一天。

### 现在的影响

上架时走的是「源无 → 保留骨架的」分支，**详情图仍是骨架商品的**。
主图（轮播图）已经是源的，这点没影响。

## 七、顺带修掉的三个坑

| 坑 | 现象 | 修法 |
|---|---|---|
| 页面保存后 commit 变成失效 id | `提交: 600001 该编辑不存在` | 默认沿用克隆得到的 commit；URL 的 id 只有通过 `commit/detail` 存在性校验才采用 |
| 页面新生成的 SKU 没有缩略图 | `请上传规格缩略图` | 用主图第一张兜底补齐（实测补了 16 个） |
| 批量切码制后尺码点击丢失 | `尺码缺 2 个` 但可用码里明明有 | `setSizes` 加第二遍补偿：对没勾上的逐个重点，最多 2 轮 |
