## 二、`[object Object]` —— 已彻底修好

### 根因

Electron 的 `executeJavaScript` 在页面抛出**非 Error 值**时，reject 出来的是一个**普通对象**。
我的 `withPlatform` 用 `String(e)` 转换，对象就变成 `[object Object]`，真实原因全丢。

同样的坑之前在 `captureEditBody` 上踩过一次，这次又出现在 `setColors` 上。

### 修法

```js
// main.js 新增 errText()
function errText(e) {
  if (typeof e === 'string') return e;
  if (e instanceof Error) return e.message;
  if (typeof e === 'object') {
    if (typeof e.error === 'string') return e.error;     // ← 关键：先看 error 字段
    if (typeof e.message === 'string') return e.message;
    ...
    return JSON.stringify(e);
  }
}
```

`withPlatform` 的 catch 和所有 `advice` 都改用 `errText`。

### 加上页面侧 try/catch

`ops.setColors` 的内部脚本现在自己捕获异常，把真实原因作为**返回值**带回，而不是让整段脚本崩掉：

```js
return { ok:false, error:'页面脚本异常：' + e.message, stack: ... };
```

### 结果：错误从「读不懂」变成「读得懂」

修之前：
```
平台操作失败[setColors]: [object Object]
建议：[object Object]
```

修之后，历次实测依次读到：
```
1. WANT is not defined                    ← 我自己加 try/catch 时引入的作用域 bug
2. Script failed to execute               ← 模板字面量里写注释，注释里的 \n 变成真实换行
3. 颜色与目标不一致 | 需要(5): 黑色/骨白色/... | 实际(5): 黑色/骨白色/...
4. 尺码没配齐（缺 5 个）：2,4,6,8,10
5. 目标店同品类骨架全部被频控拒绝（600102）
```

**每一条都能直接定位。这正是修 errText 的价值。**

## 三、中途抓出的三个连带 bug（都已修）

### bug 1：`WANT is not defined`（我引入的）

加 try/catch 时把 `const WANT` 写进了 `try` 块，但 `catch` 里要引用它 → 块作用域拿不到。
**修法**：`const WANT` 提到 `try` 外面。

### bug 2：`Script failed to execute`（我引入的）

我在模板字面量**内部**写了注释，注释里含 `\n`。
模板字面量里的 `\n` 是**真实换行**，结果注释被截断，后半句 `，否则会变成...` 变成代码 → 整体语法错误。
**修法**：注释移出模板字面量，错误信息用 ` | ` 分隔而不是 `\n`。

### bug 3：这类错误 Electron 只回一句无信息的话

**修法**：新增 `tools/check-injections.js`，用 `vm.Script` 把 15 个注入脚本全部编译一遍：

```
OK   ping / hasSaveButton / clickSaveDraft / readPageCommit / readPageErrors
OK   setBatchStock / setColors / setSizes / scrollToSpec / readSpecState
OK   listGoods / collectGoods / draftDetail / submitDraft / resolveCommit
PASS: 15 个注入脚本语法全部正确
```

**以后改 `ops.js` 先跑这个，30 秒能省几小时。**

## 五、「目标店铺没有可用的骨架商品」—— 根因是骨架太少

### 实际数据

源是 **cat 8498（羽绒服）**，目标店 **布丁2** 的库存：

| 类目 | 商品数 |
|---|---|
| **8498（羽绒服）** | **1 个** ← 唯一骨架 |
| 11985（登山鞋） | 4 个 |
| 11993（运动鞋） | 4 个 |

那唯一的羽绒服骨架已被反复克隆 → `600102`。

### 600102 是时间性限流（已实测确认）

```
03:0X  克隆成功
03:0X+1min  同一骨架再克隆 → 600102 该商品已被新建过,请勿连续新建
之后某次  又成功了
```

**窗口期平台没公开。** 所以我没有猜一个"冷却时间"硬编码，而是做了三件事：

### 修法 1：记录使用时间，按最久未用优先轮换

新增 `app/lib/skeleton.js`，落盘 `app/userdata/skeleton-used.json`：

```js
{ "1030556885674": 1794950000000 }
```

候选骨架按 `lastUsedAt` 升序排（没用的排最前）。

### 修法 2：失败时给精确诊断，不再是「换一个目标店铺」

**修之前**：
```
目标店铺没有可用的骨架商品
建议：目标店里所有商品都撞上了「该商品已被新建过」。换一个目标店铺，或等一段时间再试。
```

**修之后**：
```
目标店同品类骨架全部被频控拒绝（600102）
建议：同品类（cat 8498）骨架只有 1 个，全部被平台频控拒绝（600102）。
各骨架最近使用：
  爆款1U1U LU璐家四格鸭绒泡（1030556885674，1 分钟前用过）
全部在 15 分钟内用过。平台未公开该频控窗口，建议等 15~30 分钟，
或给目标店补充一个同品类商品（候选越多越不容易卡住）。
```

**这个建议是可执行的**：告诉你等多久、告诉你根本解法（补骨架）。

### 修法 3：日志逐条列出每个骨架的失败原因和最近使用时间

```
同品类骨架 3 个（其中 1 个从未用过），按最久未用优先
```

## 六、现在的真正卡点：尺码是「自定义」的

最后一次实测，进度推到：

```
骨架商品: 爆款1U1U（clone ok）
设颜色 需要: [...] / 实际: [...]              ← ✅ 颜色通了
尺码没配齐（缺 5 个），已停止（未提交）
缺的码: 2,4,6,8,10
```

### 根因（这是本轮最重要的发现）

查源商品的 SKU 规格：

```json
{ "parent_id": 1226, "parent_name": "尺码",
  "spec_id": 546501833, "spec_name": "2（90-100）" }
```

**`parent_id = 1226`，值是商家自己填的自由文本 `2（90-100）`。**

这意味着：**它不是「通用/中国码/欧码/英码/德码/美码/均码」里的任何一种**。
所以「遍历 7 种码制找覆盖最好」对这个商品**永远失败**——不是选错了码制，是**这个值根本不在任何标准码表里**。

### 下一步方向（未验证）

页面上的尺码区除了 7 个码制单选，还有一个**文本框**（之前探测到 placeholder 为 `未使用模板`）。
那应该就是「自定义尺码」的输入入口。

要做的是新增 `ops.setCustomSizes(values)`：
```
① 定位尺码区的那个文本框
② 逐个输入源尺码值（2（90-100） / 4（100-120） ...）
③ 每输一个按回车或点「添加」，页面生成对应复选框
④ 校验生成的码与源一致
```

**我没有盲改**，因为上一轮页面状态不稳定（规格区没渲染出来），继续猜 DOM 只会浪费你的时间。
