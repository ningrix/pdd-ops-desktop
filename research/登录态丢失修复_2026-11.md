# 登录态为什么会丢：三个叠加的坑（已全部修掉）

> 2026-11-16

---

## 一、先说结论

你每次都要重新扫码，**不是拼多多的限制，是我这边的三个 bug 叠在一起**：

| # | 坑 | 后果 |
|---|---|---|
| 1 | 同时跑着**两个应用实例** | 两个进程抢同一个 `malls.json`，写文件报 `EPERM`，店铺列表写不进去 |
| 2 | 数据目录在 `%APPDATA%`，写入被拒 | `Partitions` 目录建不出来 → **登录态从来没有落过盘** |
| 3 | 我调试时反复强杀进程 | cookie 是异步刷盘的，硬杀就丢 |

第 2 条是致命的：`Partitions` 目录根本不存在，意味着**从第一次运行到现在，所有登录态都只活在内存里**。关掉就没了。

---

## 二、怎么定位到的

### 证据 1：店铺列表从未写成功

```
malls.json 最后修改时间 = 13:48   ← 是我手动写的
应用 21:28 启动后创建了 3 个店铺
文件内容仍然是 [{"id":"mall_demo1","name":"A-羽绒服"}]
```

### 证据 2：应用自己报的错

加了一个诊断接口，把真实的写入错误打出来：

```json
{
  "userData": "C:\\Users\\56587\\AppData\\Roaming\\pdd-ops-desktop",
  "lastSaveError": "EPERM: operation not permitted, open '...\\malls.json'",
  "mallIds": ["mall_demo1", "mall_mwjbhnw51t2", "mall_mwjbhuy2xmu"]
}
```

`EPERM` + 店铺明明存在却写不进去 → 典型的**多实例抢文件**。

### 证据 3：真的有两个主进程

```
pid 57704  electron.exe --no-sandbox ...
pid 66900  electron.exe --no-sandbox ...
```

两个主进程 + 各自的 GPU/utility/renderer 子进程，一共 12 个 electron 进程。它们共用同一个 `malls.json` 和同一批 session 目录 —— 互相覆盖、互相锁。

## 三、修了三处

### 1. 单实例锁

```js
const gotLock = app.requestSingleInstanceLock();
if (!gotLock) app.quit();          // 第二个实例直接退出
app.on('second-instance', ...)     // 再次双击时把已有窗口提到前面
```

多开时不再有第二个进程去抢文件，再点桌面图标也只是把窗口唤到前台。

### 2. 数据目录搬到应用自己目录下

```
旧：%APPDATA%\pdd-ops-desktop\        ← 写入被拒
新：<应用目录>\app\userdata\           ← 可写，且是绿色便携
```

启动时 `app.setPath('userData', ...)` 在 ready 之前执行。现在：

```
app\userdata\
├─ malls.json              店铺列表（会持久）
├─ Partitions\
│  └─ mall_xxxx\           每个店铺独立 session（含 cookie）
└─ Cache\ Local Storage\ ...   Chromium 自己的
```

### 3. 退出前主动刷盘

```js
app.on('before-quit', async (e) => {
  e.preventDefault();
  for (const m of malls.values()) await session.fromPartition(m.partition).flushStorageData();
  app.quit();
});
```

正常关窗（右上角 ✕）会把 cookie 写盘。**不要用任务管理器结束进程**，那样仍会丢。

## 四、在线状态灯

左侧每个店铺前面加了一个圆点：

| 灯 | 含义 |
|---|---|
| 🟢 绿 | 在线（已登录，接口可用） |
| 🔴 红 | 离线（未登录 / 登录过期 / 页面未就绪） |
| ⚫ 灰 | 还没检测 |

- 鼠标悬停看具体原因（例如「离线：页面未就绪」）
- 添加店铺后立刻检测
- 之后每 **25 秒**自动刷新一次
- 切换店铺时也会刷新

实现方式：`ops:pingMall(id)` 针对**指定店铺**的 webContents 执行 `checkLogin`，不需要它是当前显示的那个——所以三个店的状态能同时看到。

## 五、验证记录

### 写入 + 落盘

```
debugInfo before: userData=app\userdata, exists=false, lastSaveError=null
addMall('测试店A') → {"id":"mall_mwjbj68s2y8"}
debugInfo after : exists=true, size=66, lastSaveError=null,
                  raw=[{"id":"mall_mwjbj68s2y8","name":"测试店A"}]
磁盘：app\userdata\malls.json 存在 ✅
      app\userdata\Partitions\mall_mwjbj68s2y8 存在 ✅   ← 关键
```

### 重启后还在

```
重启 → {"malls":[{"id":"mall_mwjbj68s2y8","name":"测试店A"}],
        "dots":["st off"], "names":["测试店A"]}
磁盘：malls.json 内容不变 ✅
      Partitions\mall_mwjbj68s2y8 仍在 ✅
```

**店铺 id 保持不变** → `persist:mall_mwjbj68s2y8` 不变 → 下次启动登录态还在。

## 六、坏消息：之前的店铺需要重新添加一次

因为之前从来没落盘，`店铺1 / 店铺2 / 店铺3` 的记录和登录态**无法恢复**。我已经把残留清掉了，现在是干净的。

**只需要再登录一次**，这次之后：

- 关窗再开 → 店铺在、灯是绿的
- 关机重启 → 同上
- 只要不点「✕ 移除」、不用任务管理器强杀 → 不会再丢

> 移除店铺的确认框现在会明确警告：「⚠️ 这会同时删除它的登录状态，下次要重新扫码。如果只是想重新登录，不用删，直接点该店铺再扫码即可。」
