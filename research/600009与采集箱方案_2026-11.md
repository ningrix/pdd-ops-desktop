## 一、600009 是我用错了解析方式

你的日志：

```
23:05:06 反查 commit 失败，沿用 206427103442：{"error_msg":"商品不存在","error_code":600009}
23:05:06 提交: 600001 该编辑不存在
```

`600009 商品不存在` 来自我用的 `create_by_sn`。

**`create_by_sn` 只能查在售商品，查不到草稿。** 之前它"能用"，是因为我当时查的是在售商品（源商品）。现在查的是复制出来的草稿 —— 草稿在平台眼里还不是"商品"，所以报 600009。

### 改成从页面 URL 读

编辑页的 URL 自己就带着当前 commit：

```
/goods/goods_add/index?id=<commit_id>&goods_id=<goods_id>&type=edit
```

保存后页面若换了 commit，URL 里的 `id=` 也会跟着变。所以现在的解析顺序：

```
① prep 阶段保存完，读一次 location.search 里的 id  ← 对草稿有效
② 不行再退到 create_by_sn                        ← 只对在售商品有效
③ 提交报 600001 时，再读一次 URL 重试
```

日志会写清楚来源，例如：

```
commit 已变化（来自页面 URL）：206427103442 → 2064271xxxxx
```

## 三、你问的「店二转店一」：现在做不到，原因很具体

我本来想直接测，结论可以先给：**不是参数问题，是权限边界**。

### 为什么

`copyGoodsCommit` 的语义是「**克隆我自己店铺里的商品**」。它要求 `source_goods_id` 在**发起请求那家店的权限范围内**。

用店铺1 的登录态去克隆店铺2 的商品，平台会拒绝——因为店铺1 的 session 根本看不到店铺2 的商品数据。

### 跨店真正需要什么

```
店铺2 的 session：读取商品 → 落地成"数据包"（本地文件）
店铺1 的 session：用数据包 → 新建商品（不是克隆）→ 提交上架
```

**难点在第二步**：我们目前只有「克隆本店商品」这个接口，**没有「从零新建商品」的接口**。

从零新建要走发布页那条链：
- 类目属性（`goods_property_list`）
- 规格/SKU 重建
- 图片上传（CDN 签名）
- 服务模板

这些字段的 schema 我还没抓到。**这是跨店复制唯一的拦路石。**

## 四、「已抓取的商品放新栏目」—— 方向完全正确

你说的这个，正是跨店复制的**前置模块**，叫「采集箱 / 商品池」。它解决三件事：

### 1. 采集与上架解耦

```
现在：选店铺 → 读商品 → 立刻复制（绑死在一家店里）
应该：读商品 → 入池（本地保存）→ 从池里选 → 上架到任意店铺
```

### 2. 跨店的前置

池子里存的是**数据包**，不依赖任何店铺的 session。店铺2 抓的包，店铺1 可以拿来用。

### 3. 可复用、可审核

抓一次存下来，可以反复用；上架前能在池子里先改标题/价格/图，再批量提交。

### 建议的池子结构

```
app\userdata\pool\
├─ index.json                 池子索引（商品列表 + 状态）
└─ <goods_id>\
   ├─ meta.json              标题/价格/SKU/规格/属性/运费模板
   ├─ images\                主图 + 详情图（本地缓存）
   └─ raw.json               原始接口返回（留证据，便于重放）
```

每个商品带状态流转：

```
已采集 → 已处理（改好价/标题）→ 待上架 → 已上架 → 失败（附错误码）
```

### 界面

左侧加第 ④ 个区块「采集箱」，或者右侧加一个 tab：

```
[商品列表] [采集箱] [浏览器] [原始结果]

采集箱
┌────┬──────────────────────┬────────┬────────┬──────────┐
│ 图 │ 标题                 │ 拼单价 │ 状态   │ 操作     │
├────┼──────────────────────┼────────┼────────┼──────────┤
│ 🖼 │ lu鸭绒羽绒服…        │ 330.88 │ 已采集 │ [上架]   │
│ 🖼 │ 山行2代 GTX…         │ 228.88 │ 待上架 │ [上架]   │
└────┴──────────────────────┴────────┴────────┴──────────┘
```

**同店上架**：池子里的包 → 走现在的 `copyGoodsCommit`（如果源在同店）
**跨店上架**：需要一个"从零新建"通道 —— 这是要攻的下一个接口
