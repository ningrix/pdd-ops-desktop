# 提交上架失败的真实原因（3000000 → 10000014）

> 2026-11-16

---

## 一、3000000「缺少goodsId」是我传参的锅，不是接口要求变了

我逐组试了参数名：

| 参数组合 | 平台返回 |
|---|---|
| `{goods_id, goods_commit_id}` | **`10000014 尺码表参数或组别不能为空`** ← 过了参数校验 |
| `{goodsId, goodsCommitId}` | `2000000 商品编辑版本号为空` |
| `{goodsId, goods_commit_id}` | `3000000 参数不合法，缺少goodsId` |
| `{goods_id, goodsId, goods_commit_id, commit_id}` | `10000014 尺码表参数或组别不能为空` |
| `{goods_id, commit_id}` | `2000000 商品编辑版本号为空` |

**结论：接口参数就是 `{goods_id, goods_commit_id}`（下划线），本来就对。**

你看到 3000000 是因为我 `submitDraft` 里把 `goods` 拼成了 `0`（模板里嵌套 `Number()` 时字符串变成 NaN → 0），实际发出去的是 `goods_id: 0`。

**已修**：`submitDraft` 现在如果拿不到 `goods_id`，会自己调 `commit/detail` 反查，不再可能发 0。

## 二、现在真正的拦路虎：尺码表

```
{"error_msg":"尺码表参数或组别不能为空","error_code":10000014}
```

这是**业务校验**，不是参数问题。拼多多按类目要求：鞋服类商品必须有尺码表才能上架。

这个草稿（登山鞋，cat_id 11985）的 `size_spec_id` 是空的 —— 因为它从源商品克隆时，源商品本身就没配尺码表（无货源商品的常见情况）。

### 为什么点 UI 按钮也没反应

我用 `element.click()` 和真实鼠标事件（`Input.dispatchMouseEvent`）各试了一次，**页面一个请求都没发**。原因就是页面跑的是同一套业务校验，尺码表没填 → 直接拦下，连接口都不打。

所以「卡在提交」这件事，改代码解决不了，得先补数据。

### 三种解法

| 方法 | 说明 | 适合 |
|---|---|---|
| **换一个有尺码表的商品复制** | 源商品本身配好了尺码表，克隆过来就能直接上架 | 最快，立刻可验证 |
| **在编辑页补一次尺码表** | 打开草稿 → 尺码表区域 → 填/导入 → 保存 | 单品修复 |
| **做批量尺码表模板** | 按类目准备尺码表，复制后自动套用 | 长期，工程量大 |

## 三、顺带纠正一个我之前说错的结论：库存

之前我说「`quantity_delta` 写进去不落库」——**错了，是能落库的**。

实测流程（用编辑页的「批量设置」）：

```
1. 在「批量设置」的库存输入框填 100
2. 点「批量设置」按钮 → 60 个 SKU 全部变成 100
3. 点「保存草稿」→ 抓到的载荷里 skus[].quantity_delta 全是 100
4. 刷新编辑页 → 库存输入框显示 100   ✅ 确实存住了
```

但 `commit/detail` 里：

```
skus[0].quantity       = 0     ← 一直是 0
skus[0].quantity_delta = 100   ← 真实库存存在这里
```

**所以：草稿的库存字段是 `quantity_delta`，`quantity` 只在商品真正上架后才有值。** 我之前看到 `quantity: 0` 就下结论"不落库"，是看错了字段。

对程序的含义：
- 改库存 = 把 `quantity_delta` 设成目标值（可以直接走 `action/edit` 回放，不必点 UI）
- 判断"有没有库存"要看 `quantity_delta`，不能看 `quantity`
