## 核心结论（一句话）
方向成立，但 300 元 + 无店铺不能同时完成「卖货 + 积累现金」；300 元只能做 14 天需求验证，首轮只做无 IP 白牌，避开奶龙/臭企鹅/游戏二创/AI 娘化/无授权正版。

## 一、要回答的核心问题
用不超过 300 元，能否找到「合法来源清楚 + 履约可执行 + 扣完成本仍有正贡献利润」的周边商品？
本报告服务于「先卖热门周边积累现金」的首轮验证，不默认囤货，不把未授权 IP 当成可自由商用。

## 二、硬性约束
1. 不编造价格、销量、授权状态；查不到就写「待核实」。
2. 每条关键数据必须带：来源 URL、抓取/发布日期、证据等级。
3. 证据等级：
   - A：平台/官方页面直接读取（如 m.1688.com 内嵌 JSON、拼多多官方规则/公告、法院或官媒原文）
   - B：搜索摘要或第三方报道，可定位来源但未打开原文
   - C：行业经验/模型假设，必须标注「假设，需人工核实」
4. 供应商页面出现「代发」入口 ≠ 支持发拼多多电子面单、≠ 48h 发货、≠ 有 IP 授权。三者必须分开写。
5. 授权状态只能写「页面未展示」「商家自称」「需索取授权链」；不得推断为已授权。

## 三、实测网络抓取备忘
- web_search 可用，但偶发 "DeepSeek search request failed: fetch failed"，等几秒重试 1–2 次即可。
- 1688：PC 的 detail.1688.com 会触发反爬（返回 punish 页）。改用 https://m.1688.com/offer/{offerId}.html ，页面内嵌 JSON：可搜 "blackPage":{"offerTitle"、"price":"¥0.33 ~ ¥0.50"、"sceneKey":"consign","sceneName":"代发"、服务、meta location。
- 找 offerId：web_search 查 site:detail.1688.com 关键词，sources 的 url 即 offer 链接。
- 拼多多移动端 search_result.html 是前端渲染壳（约 48KB 无商品数据），不要花时间解析；用搜索摘要、第三方比价/榜单、社媒内容。
- 微软 Bing HTML 对中文分词很差，优先 web_search。
- 1688 每次请求间隔 5–10 秒；连续请求 4 次后会触发 x5secdata 反爬，冷却需 ≥30–60 分钟；被封就换下一个 offer 并标注「本次未取到」。
- 义乌国际商贸城官方 chinagoods 商品详情页可直接读取价格/起批/发货时效，是 1688 被封时的可靠替代。
