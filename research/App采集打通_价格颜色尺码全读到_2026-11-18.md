| iPhone UA | 跳 App 下载页 | — |
| 微信 UA + 390×844 设备模拟 + 触屏 | 打码 | 空 |
| 安卓 UA + 设备模拟 | 打码 | 空 |

### 工作流程

```
① adb am start -a android.intent.action.VIEW
     -d "pinduoduo://com.xunmeng.pinduoduo/goods.html?goods_id=XXX"
② 轮询 uiautomator dump，等标题出现（最长 35 秒，实测约 20 秒）
③ 解析详情页：标题 / 价格 / 价格档 / 销量
④ 找「发起拼单」按钮，人类式点击打开 SKU 弹层
⑤ 轮询 dump，解析颜色 / 尺码 / 规格提示
⑥ 输出 JSON
```

## 四、踩到的坑（都记在代码注释里了）

| 坑 | 现象 | 解法 |
|---|---|---|
| **必须用自定义 scheme** | `http(s)` 链接会打开浏览器，不是 App | `pinduoduo://com.xunmeng.pinduoduo/goods.html?goods_id=` |
| **加载要 15~25 秒** | 等 9 秒只读到空白/图片 | 轮询 dump，等到标题出现为止 |
| **SKU 弹层浮在详情页上** | 两个页面的文字混在同一个 dump 里，颜色抓到 31 个（全是详情页文案） | 取**最后一次出现**的 `颜色分类` / `尺码` 标签 —— 弹层渲染在详情页之后 |
| **标题抓到法律文案** | 「服饰类商品如出现已洗涤…不支持七天无理由退换」 | 标题在价格节点之后；排除 `消费提醒/七天无理由/券$/优惠前` 等；要求含中文；取最长候选 |
| **标题抓到资源文件名** | `7cab5d0d-...gif.slim` | 排除 uuid / 长 hash / `.gif\|.png\|.slim` 等 |
| **尺码段拖尾** | 混进「一次选多款」「立即支付」 | 严格匹配尺码形态（`36` / `39.5` / `2（90-100）` / `150/72A` / `XL`），遇到第一个不匹配就停 |
| **颜色标签名不统一** | 有的是「颜色」有的是「颜色分类」 | 四个标签都兼容 |

## 五、和网页端的分工（互补，不是替代）

| 数据 | 从哪拿 | 原因 |
|---|---|---|
| **价格 / 颜色 / 尺码** | **App** | 网页端服务端打码，拿不到 |
| **标题** | 两边都行（App 更快） | — |
| **主图 / 详情图** | **网页端** | App 里的图在缓存里，导出麻烦；网页端 `detailGallery` 一次给 11 张 |
| **商品属性**（填充物/绒含量/版型…） | **网页端** | 网页端 `goodsProperty` 是结构化数组，App 里要 OCR |

**所以完整采集 = App 拿价格规格 + 网页拿图片属性。**

## 七、一句话

> **价格、颜色、尺码（包括 `2（90-100）` 这种自定义码）全部能从 App 读到，端到端实测通过。**
>
> 这是网页端物理上做不到的事 —— 服务端打码，换任何 UA、任何设备模拟都没用。
>
> 剩下的就是拿一个别人家的 goods_id 试一次，然后接进界面。
