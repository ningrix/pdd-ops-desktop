# 功能可复现性判定：截图里那 8 个功能，哪些能做、怎么做

> 2026-11-16 ｜ 结论面向「复制上架 + 功能全集」，加价幅度不作为设计目标

---

## 一、先回答你最关心的：复制上架能不能做

**能，而且有公开验证过的路径，不是我推测的。**

`yinnho/aginxbrowser` 的 `pinduoduo-publish` flow 在 **2026-10-12 已跑通并留了回执**：

```
已登录 MMS 会话
  → __mms.fetch.sync（同步 XHR，与页面自身请求同指纹）
  → copyGoodsCommit          克隆，图/SKU/属性随 copy 继承
  → update_goods_commit_info 改名（必带 cat_id，禁止传 out_goods_sn）
  → commit/detail            草稿回读
  → commit/submit            公开提交（单次，不盲重试）
  → goodsListByGoodsId       在售回读
```

**实测数据**：草稿 `goods_id=1015378324592` / `commit=203445014447`，标题「TEST-RAW-奇骏钢化膜草稿-勿拍-20261012」，`is_shop:0`，**13 图 / 4 SKU**，从未打 submit。真发一次耗时 114.3s（页面启动 46s、登录检查 30.2s、copyGoodsCommit 31.8s、提交 0.7s、核验 4.7s）。

关键结论：
- **图片和 SKU 不用自己传**——copy 会继承源商品的 CDN gallery 和全部 SKU
- **`action/edit`（从零拼字段）已证失败**，报「价格参数不完整」/ 4000000，不要走那条路
- **永不包装 `window.fetch`**（PDD 指纹会识破）
- 默认 `submit:0` 只存草稿，安全

我把这条链封装成了可直接跑的脚本：`work/pdd_copy_publish.js`
在已登录的 `mms.pinduoduo.com/home/` 控制台粘一次，跑 `PDDC.list()` 就能看到你店里的商品和 `goods_id`，然后 `PDDC.copyAndPublish(0, "新标题")` 就会产出第一条草稿。

### 一个重要的资质差异

截图里那个工具在**拼多多服务市场**卖，走官方开放平台接口 → 需要**企业 ISV 资质**（营业执照 + 门头视频 + MRD/PRD）、敏感接口强制云内部署（约 4800 元/年）、服务市场按结算收入 0.6% 交技术服务费。

**你自建走的是「已登录商家后台的 MMS 接口」，属于模拟后台操作，不是调开放平台 API → 不需要任何 ISV 资质，零资质成本。** 这是自建相对服务市场工具的硬优势之一。

## 二、8 个功能的可复现性判定

| # | 功能 | 能复现 | 核心依赖 | 难度 | 需要注意 |
|---|---|---|---|---|---|
| 1 | **复制上架** | ✅ 路径已验证 | `copyGoodsCommit` + 已登录会话 | 低 | 源必须是**你已授权店铺**的商品；跨店抓别人是另一条风险线 |
| 2 | **批量编辑** | ✅ | MMS 商品/草稿编辑接口，或逐条 commit 改 | 中 | 改价受平台比价规则约束（不是硬拦，是事后限流） |
| 3 | **产品裂变** | ✅ | copy × N + 每条改标题/主图/SKU | 中 | 差异化不够 → 判重复铺货。质量全在差异化，不在复制 |
| 4 | **商品检测** | ✅ | 纯本地规则引擎 + 平台「商品体检」页读回 | 低 | 规则库要自己维护（违禁词、属性缺失、图尺寸、低价引流） |
| 5 | **标题 AI 优化** | ✅ | LLM + 类目热搜词数据 | 低 | 没有词数据就是瞎编，等于随机后缀的高级版 |
| 6 | **主图优化** | ✅ **你的强项** | 你已有的 LaMa / mask / OCR / 超分管线 | 中 | 必须做「真差异」不是「伪差异」——平台 2026 在严打后者 |
| 7 | **主图视频** | ✅ | ffmpeg 合成（图片序列 + 转场 + 字幕） | 中 | 平台对时长/尺寸/码率有规格要求，要按类目对表 |
| 8 | **多店铺管理** | ✅ 但最重 | 多会话登录态隔离 + 任务队列 + 店铺权限 | **高** | 这是团队版唯一的真复杂点，也是市面工具卖得最贵的地方 |
| 9 | **主图水印** | ✅ | PIL / Canvas 叠加 | 低 | ⚠️ 加水印**对避重无效**，只适合品牌化，别当差异化手段 |

**八项没有一项需要外部许可、第三方付费服务或特殊数据源。** 唯一的硬依赖是「已登录的商家会话」；最重的一项是登录态托管。

### 逐条给判断

**① 复制上架** — 已解决。上面那条链就是全部。

**② 批量编辑** — 能做，但要注意：**批量编辑的价值不在"能改"，在"改完不出错"**。改价最容易出资损（倍数写反、SKU 错位），所以必须配回读校验。这也是全行业空白，你做了就领先。

**③ 产品裂变** — 技术上就是 copy 循环 + 每次替换标题和主图。真正决定成败的是：平台判同款的 6 个维度（主图 / SKU 图 / 标题关键词 / 属性 / 详情文案 / 规格名称）里，你能改掉几个。你手上有本地图像管线 + 词根重组能力，这两项正好覆盖最难的「主图」和「标题」。**裂变做得好不好，本质是图像和文案能力，不是复制能力。**

**④ 商品检测** — 纯本地，零平台依赖，最好做。而且和「上架前风险打分」是同一套东西：
- 违禁词/极限词（本地词库）
- 类目属性缺失（对比类目模板）
- 主图尺寸/白底（本地图像检查）
- 低价引流（SKU 价差 > 30%、标题量词与最低价 SKU 不匹配）
- 同款相似度（pHash / CLIP 对你店内已有商品）

**⑤ 标题 AI 优化** — LLM 部分十分钟的事。难的是「优化依据」：需要类目热搜词、竞品标题词根、你自己成交词的转化数据。**没有数据的 AI 标题优化 = 随机后缀的豪华版**，竞品正在这么干。

**⑥ 主图优化** — 你 workspace 里已经有整套：LaMa 重绘、mask 生成、OCR 标注、批量去水印、超分。竞品的「AI 换图」是调第三方 API 或模板合成，一眼假。**这是你相对所有竞品的最大技术优势。**

**⑦ 主图视频** — ffmpeg 就能做：主图序列 → Ken Burns 推拉 → 转场 → 字幕 → 出 mp4。中等工作量，主要成本是摸清每个类目的规格要求（时长、比例、大小上限）。

**⑧ 多店铺管理** — 唯一的「高」难度项。要解决：
- 多个店铺的登录态怎么并存（同浏览器多 profile / 多容器）
- 任务怎么按店铺隔离（一家店被限流不能拖垮其他店）
- 谁能操作哪个店（团队版权限）
- 全局限速和日配额（防止团队一起上货触发关联识别）
这不是技术难点，是**工程复杂度**——也是为什么市面工具按店收费。

**⑨ 主图水印** — 最简单的一项，但要提醒：**平台图像指纹识别对"加个水印/换个色调"这种改动基本无效**，2026 年的判定已经不看这个了。水印只适合品牌化，别写进"避重"功能里，会误导团队。

## 三、按你的实际目标重排优先级

你不在乎加价，在乎「复制上架 + 功能复现」。那 P0 就该这么切：

```
第一层｜能干活（1~2 周）
  1. 复制上架闭环        已验证路径，直接封装
  2. 商品库（本地）      SQLite + 图片缓存 + 状态流转
  3. 批量编辑 + 回读校验  改完必须能确认改对了
  → 做完这三项，团队就能替代截图那个工具的主力功能

第二层｜能规模化（2~3 周）
  4. 产品裂变（copy × N + 差异化）
  5. 标题词根重组
  6. 主图差异化（接你的图像管线）
  7. 商品检测 / 上架前风险打分

第三层｜能协作（2 周）
  8. 局域网 Web + 账号权限 + 任务队列 + 审计
  9. 多店铺登录态托管

第四层｜锦上添花
  10. 主图视频    11. 主图水印（品牌化用途）
```

**关键判断**：截图那个工具的功能列表里，最值钱的是「复制上架 + 批量编辑 + 多店铺」，最不值钱的是「主图水印」。而它把「加价」写那么大，是因为那是它唯一能拿捏用户的点——**你既然不在乎加价，那它对你就没有护城河了**。
