## 二、为什么这条路能解决价格/规格问题

我这一轮把网页端的所有可能性都试过了，结果都是失败：

| 尝试 | 结果 |
|---|---|
| 纯 HTTP 抓取（无登录） | `needLogin: true` |
| 登录后桌面 UA | 价格打码 `3??.88`，`skuProperty: []` |
| iPhone UA | 跳 App 下载页 |
| 微信 UA + 设备模拟 390×844 + 触屏 | 价格打码、规格空 |
| 安卓 UA + 设备模拟 | 价格打码、规格空 |
| 点「发起拼单」 | **页面上根本没有这个按钮** |
| 全量搜 `oakData` 找规格 | **0 处命中** |

**结论：价格和规格是服务端不下发，不是客户端渲染问题。** 换 UA、换设备、模拟手机全都无效。

而 **App 拿到的数据是完整的**（App 里能看到颜色、尺码、精确价格）。所以用真 App 是对的方向。

## 三、两条路对比

| | 模拟器（BlueStacks/MuMu） | 真机 + ADB |
|---|---|---|
| 成本 | **0 元** | 一台旧安卓机，几百元 |
| 安装时间 | 半天（含首次配置） | 1 小时 |
| 数据完整度 | 完整 | 完整 |
| **风控风险** | ⚠️ **PDD 可能识别模拟器**（未验证） | ✅ 最低 |
| 稳定性 | 一般（会卡、会崩） | 好 |
| 多开 | ✅ 支持 | ❌ |
| 自动化难度 | 中（ADB 坐标/tap/dump） | 中 |

### 最大的不确定性：风控

拼多多对模拟器的识别是业内比较严的。可能出现：
- 登录时要求滑块验证 / 人脸
- 提示「当前环境异常」
- 能浏览但下单/看价格受限

**这一条只有实际跑起来才知道。** 所以我建议先做最小验证，不要一上来写脚本。

## 四、但必须说清：这只解决采集

| 环节 | 模拟器能不能解决 |
|---|---|
| 读别人的商品（标题/图/属性/价格/规格） | ✅ **能** |
| 存进采集箱 | ✅ 能 |
| **上架到你的店** | ❌ **不能** |
| **自定义尺码（`2（90-100）`）** | ❌ **仍然不能** |

因为上架还是走商家后台网页（空白新建 / 骨架克隆），那条路的能力不会因为采集端变强而改变。

**除非**：拼多多商家版 App 也能发布商品。但：
- App 发布功能比后台弱（不能批量、规格编辑受限）
- 自动化 App UI 比网页脆弱得多（坐标、滑块、页面随时改版）

所以我的判断：**模拟器解决采集，不解决发布。**

## 五、装完之后的最小验证（半天，别急着写脚本）

```
① 模拟器里装拼多多 APK
② 用手机号登录（这一步可能触发风控，看结果）
③ 打开一个商品页
④ 用 ADB 做三件事：
   adb shell uiautomator dump        # 导出界面结构
   adb exec-out screencap -p > 1.png # 截图
   adb shell input tap X Y           # 点击
⑤ 看 dump 出来的 XML 里有没有：
   - 颜色选项（黑色/白色/...）
   - 尺码选项（S/M/L 或 2/4/6）
   - 精确价格（¥XXX.XX）
```

**三个都有 → 路线成立，我写采集脚本。**
**被风控拦住 → 换真机，或者放弃采集别人商品这条路。**
