## 一、找到的方案：Playwright（不是插件，是库）

环境里**没有**浏览器类 MCP（只有 `rea`）、也没有浏览器 skill。
但我找到了更合适的东西：**Playwright 的 `connectOverCDP`**。

### 为什么这个方案最合适

| 方案 | 问题 |
|---|---|
| 浏览器插件（Tampermonkey 之类） | 只能跑在页面里，不能做多页面编排、不能读写本地文件、不能调 Python |
| 电脑控制插件（键鼠模拟） | 靠坐标点，窗口一动就错，中文输入法还会打断 |
| MCP 浏览器服务 | 环境里没装 |
| **Playwright connectOverCDP** | ✅ **直接接管我们 Electron 应用已开的浏览器**，登录态复用、不用重新扫码 |

### 实测结果

```
npm install playwright-core@1.65.1   （13.9MB，纯 JS，无原生编译）
```

```js
const browser = await chromium.connectOverCDP('http://127.0.0.1:9333');
```

输出：

```
✓ 已连接，版本: 144.0.7559.236
上下文数: 1
上下文[0] 页面数: 3
  - file:///.../app/renderer/index.html   (拼多多上货中台)
  - https://mms.pinduoduo.com/home/       (首页)
  - https://mms.pinduoduo.com/home/       (首页)
```

**接入零成本**：我们的应用本来就带 `--remote-debugging-port=9333`，
Playwright 连上去就能用 `getByPlaceholder` / `setInputFiles` / 自动等待 / 截图 / 进 iframe。

**关键约束**：`playwright-core` 是纯 JS，不下载浏览器、不需要编译器，符合 AGENTS.md §1.3.4。

### ⚠️ 踩到的坑（都已绕过）

| 坑 | 现象 | 解法 |
|---|---|---|
| 标题必须和图片匹配 | 用「测试-PW-空白新建」→ 平台报「暂无推荐的分类」 | 用源商品真实标题 |
| 「下一步」点不动 | Playwright `click()` 等待"元素稳定"超时（有遮罩） | 用 JS 直接 `el.click()` |
| 颜色选择器误匹配 | `[class*="new-spec-single-color"] input` 匹配到隐藏的 `input[type=file]` | 限定 `input[type=text]` |
| 截图超时 | 页面太重，`page.screenshot()` 30 秒超时 | 改用 DOM 读取代替截图 |

## 三、这一轮最重要的发现：尺码的真面目

### 「自定义尺码」不是我以为的东西

我一直以为它是「加一个自定义尺码值」的输入框。实测输入 `2（90-100）` 后，页面上出现的是：

```
肩宽(cm)  胸围(cm)  臀围(cm)  身高(cm) 重要  体重(kg) 重要  腰围(cm)  区间值
```

**这是尺码表的「列定义」（参数表头），不是尺码值。**

和之前抓到的尺码表接口对上了：

```json
{content:{meta:{groups:[{id:1}], elements:[{id:10004}]}, records:[...]}}
                                      ↑ elements 就是这些列
```

### 空白新建页，尺码值只能从标准码表勾选

把规格区所有可点元素扫了一遍（容器 `goods-spec-sku-v2`）：

```
尺码
  可从尺码表模板选择尺码  [全部尺码表]
  通用 / 中国码 / 欧码 / 英码 / 德码 / 美码 / 均码
  [全选以下规格值]
  150/72A 150/76A 155/80A 160/84A 165/88A 170/92A
  170/96A 175/100A 175/104A 180/108A 180/112A
  [自定义尺码排序]        ← 只是排序，不是添加
```

**没有「自由添加尺码值」的入口。**

### 「全部尺码表」跳转到了别的地方

点它会导航到：

```
https://mms.pinduoduo.com/goods/size/list?classId=1&leafClassId=7
```

**这是尺码表管理页**，不是模板选择弹窗。

### 所以：`2（90-100）` 这种自定义尺码值，空白新建页造不出来

**这解释了一件事**：为什么官方 API 里要有 `pdd.goods.spec.id.get` —— 那是**唯一能自由创建规格值**的入口。
网页端只能让你从标准码表勾，或者先建一张尺码表。

## 五、现在的完整判断

### 空白新建能做什么

| 商品类型 | 能否空白新建 |
|---|---|
| 尺码是**标准码**（36~45 / S/M/L / 国标号型） | ✅ 能。传图→类目→属性→颜色→勾标准码→价格库存→保存 |
| 尺码是**自定义值**（`2（90-100）` 这类） | ❌ 网页端没有自由入口，只能先建尺码表 |

### 三条路径的最终定位

| 路径 | 适用 | 状态 |
|---|---|---|
| **C · 空白新建** | 标准尺码商品，任意店铺（不依赖骨架、无 600102） | 传图/类目/属性/颜色已通；价格库存提交未做 |
| **B · 骨架克隆** | 已有同品类骨架、要求快 | 通，但受 600102 和骨架码表限制 |
| **官方 API** | **所有情况，尤其自定义尺码** | 待入驻审核 |

**关键结论：自定义尺码这个问题，网页端绕不过去。**
`pdd.goods.spec.id.get` 不是"更好用的替代"，是**唯一解**。

## 七、Playwright 要不要正式引入

**要。** 理由：

| 现在（裸 CDP + executeJavaScript） | 用 Playwright |
|---|---|
| 手写 `document.querySelector` 猜 class | `getByPlaceholder('自定义尺码')` / `getByRole('button', {name:/下一步/})` |
| 自己轮询等元素出现 | 内置自动等待 |
| 自己处理 iframe 上下文 | `frameLocator()` 一行 |
| 合成事件（React 可能忽略） | **CDP 可信事件**（`fill` / `press` 都是真事件） |
| 文件上传要自己调 `DOM.setFileInputFiles` | `setInputFiles()` 一行 |
| 没有现场留证 | 截图 / trace 可留证 |

**代价**：多 13.9MB 依赖，纯 JS 无编译。

**建议**：把 Playwright 作为「DOM 驱动类任务」的执行层，
现有的 `ops.js` 保留（走页面 `__mms` 的接口调用仍然更轻更快）。
两者分工：**调接口用 ops.js，点页面用 Playwright。**
