## 四、「点添加就卡死，只有浏览器能动」—— 两个叠加的 bug

### Bug 1：`window.prompt()` 在 Electron 里不存在

Electron 的 renderer 移除了 `prompt`。一点「＋ 添加」就抛 `prompt() is and will not be supported`，异常没人接 → 界面毫无反应。

**修复**：自绘弹窗（`#modalMask` + `askText()`）。

### Bug 2（真正的"卡死"原因）：原生浏览器视图盖住了弹窗

`WebContentsView` 是**原生层**，永远渲染在 HTML 之上。修好 Bug 1 之后弹窗确实创建了，于是出现你看到的现象：

- 半透明遮罩 `position:fixed; inset:0` 覆盖整个窗口 → **左栏变暗**
- 遮罩在 HTML 层，被原生浏览器视图挡住 → **浏览器区域照常显示，还能点**
- 对话框在窗口正中 → **正好落在浏览器视图覆盖的区域，被完全遮住**
- HTML 层的点击被遮罩吃掉 → 界面"卡死"，只有浏览器能操作

**修复**：弹窗打开前先把浏览器视图摘掉（`toggleView(false)`），关闭后恢复，再重算布局。

### 验证（程序化，不是目测）

用 `--remote-debugging-port` 驱动渲染进程点了「＋ 添加」，然后读几何：

```json
{
  "dpr": 2.52,
  "innerW": 1133, "innerH": 649,
  "maskDisplay": "flex",
  "modalRect": [377, 241, 380, 167],
  "inputRect": [395, 292, 342, 36],
  "activeEl": "modalInput"
}
```

弹窗中心 = (377+190, 241+83) = **(567, 324)**，视口中心 = (1133/2, 649/2) = **(566.5, 324.5)** —— 精确居中，输入框已聚焦。截图也确认可见。

> 顺带说明：我的截图看起来弹窗偏到右下角，是因为 PowerShell 不感知 DPI（这台机器 `devicePixelRatio = 2.52`），`PrintWindow` 拿到的是缩放后的坐标。实际屏幕上是居中的。

### Bug 3（这是你双击没反应的元凶）：bat 里的中文注释

`启动.bat` 之前写了中文注释。cmd 的默认代码页是 GBK，UTF-8 的中文字节被拆错，**整行被当成命令执行**：

```
'境必须清掉' is not recognized as an internal or external command
'l' is not recognized as an internal or external command
```

所以双击.bat 或者快捷方式，都是"什么都没发生"。**已改成纯 ASCII**（0 个非 ASCII 字节），并加了 `launch.log` 记录每次启动。

## 五、启动日志（排查用）

每次启动会往 `app\launch.log` 追加：

```
[2026/11/16 21:07:08.78] launcher start, cwd=...\app
    ELECTRON_RUN_AS_NODE=[]
    launching node_modules\electron\dist\electron.exe
    start returned errorlevel=0
```

如果哪天点了没反应，先看这个文件最后几行。

> 注意 `ELECTRON_RUN_AS_NODE` 这一行：如果是 `[1]`，说明启动环境带着这个变量，Electron 会退化成纯 Node、窗口起不来。bat 里已经 `set "ELECTRON_RUN_AS_NODE="` 清掉，但如果你从某些开发终端里启动，仍可能被继承。
