## 二、匹配逻辑

原先有个 bug：`men_top` 的关键词里有「外套 / 羽绒服」这种**不限性别**的词，会把女装也匹成男装模板。

现在的匹配顺序：

```
① 品牌/款式模板优先
   lululemon_jacket、kailas_gt5000（id 不以 men_/women_ 开头）
   —— 品牌名命中就赢，不管性别

② 性别过滤
   类目名里出现「女」→ 只允许 women_*
   出现「男」→ 只允许 men_*
   都没有 → 男/女模板都参与

③ 关键词包含匹配
   match 数组里任一关键词被「类目名拼接串」包含即命中
```

### 实测（程序化验证）

```
女装/女士外套/羽绒服   → 女装上衣            [XS,S,M,L,XL,2XL,3XL]
男装/男式羽绒服        → 男装上衣（国标号型）  [XS,S,M,L,XL,XXL,XXXL]
女鞋/单鞋             → 女鞋（欧码/中国码）   [34..41]
男鞋/登山鞋           → 男鞋（欧码/中国码）   [39..46]
女装/露露同款羽绒服     → Lululemon 短款      [2,4,6,8,10]   ← 品牌优先生效
运动户外/户外服装       → 无匹配（关键词没覆盖，可自行补）
未知类目              → 无匹配
```

## 四、写入通道：接口找到了，schema 还没拿到

这是目前唯一卡住的一环。

### 已确认

| 探测 | 结果 |
|---|---|
| `POST /glide/forward/cabernet/mms/sizespec/action/post` | **存在**（返回 `4000000 系统异常` = 参数不对，但路由通） |
| `.../action/query`、`/get`、`/detail`、`/list` | 都是 `ERR_NO_PERMISSION`（这些路径不存在） |

### 拿不到 schema 的原因

拼多多的尺码表是**在编辑页里填的**，保存时页面自己拼 body。我试过直接猜字段，服务端只回「系统异常」，不给字段提示。

### 需要你配合一次（约 2 分钟）

这是唯一需要手动的一步，做完之后就能全自动：

```
1. 打开某个鞋/服的草稿编辑页
   （应用里复制出来的草稿 → 商品管理 → 草稿箱 → 编辑）
2. 找到「尺码表」区域，随便填一套（用我给你的模板也行）
3. 点「保存尺码表」
4. 告诉我一声，我同步抓 action/post 的完整请求体
```

抓包工具已就位：

```powershell
python tools\cdp_capture.py --click "保存尺码表" --seconds 30 --match sizespec,cabernet
```

拿到 body 之后，我就能：

- 把模板 JSON 直接转成这个接口的 payload
- 在复制流程里加一步：`复制 → 套尺码表 → 改价 → 上架`
- 到那时「一键上架」才算真正闭环

## 五、后续可以做的增强

模板库现在是最小可用版本，后面可以加：

1. **按 cat_id 精确映射**（现在是类目名关键词，改名就失效）
2. **从源商品自动学习**：源商品本来有尺码表的，直接克隆过来，不用模板
3. **模板编辑器 UI**：不用改 JSON，界面上增删改
4. **尺码表图片生成**：把模板渲染成你截图那种图片（你那套图像管线能做），顺便当主图/详情图用

第 4 项其实是白捡的——模板数据 + 你这边的作图能力，可以批量产出「尺码表图片」，这在详情页里是转化率很高的素材。
