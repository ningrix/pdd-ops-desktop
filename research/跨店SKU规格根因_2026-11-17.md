## 一、最重要的结论

**`action/edit` 接口不修改 SKU 规格树。** 它只吃标题 / 图片 / 价格 / 库存，
规格部分被**静默丢弃**——返回 `{"ok":true}`，但重新加载页面后规格一模一样。

实测证据（同一个草稿，连续三轮）：

```
[1] 打开草稿，抓到骨架原始载荷：skus = 44
[2] 用源的 64 个规格重建 skus（id=0, sku_id=0），其余字段深拷贝骨架模板
    重建后 skus = 64
[3] 保存 → {"ok": true, "d": true}          ← 接口说成功了
[4] 重新加载页面，再抓一次载荷：
    skus = 44                                ← 根本没变
    spec = [纽扣款-灰, 39]                   ← 还是骨架的规格
```

**结论：克隆出来的草稿，规格树是锁定的。跨店搬规格不能走「骨架 + 覆盖」这条路。**

## 二、顺带查清的两个 UI 入口

| 入口 | 能做什么 | 不能做什么 |
|---|---|---|
| **Excel批量编辑规格** | 改库存、拼单价、单买价、规格编码、状态 | **不能增删规格行**（弹窗原文：「可修改规格库存、拼单价、单买价、规格编码和状态，包含0个未启用规格」） |
| **添加规格类型** | 应该是改规格结构的入口 | 本次探测被残留弹窗挡住，未拿到它调的接口 |

`groups` 字段是**团购设置**（`customer_num` / `buy_limit` / `group_price`），
**不是规格树**——之前我按名字猜错了。规格树完全在 `skus[].spec[]`：

```json
"spec": [
  {"parent_id": 8640,  "parent_name": "颜色分类", "spec_id": 49751,     "spec_name": "黑色", "is_custom": 0},
  {"parent_id": 26908, "parent_name": "鞋码",     "spec_id": 546501833, "spec_name": "2（90-100）", "is_custom": 0}
]
```

`parent_id` 是**类目绑定的规格组**（鞋码 26908 / 服装尺码 1226），
`spec_id` 是**每个商品私有的规格值 id**——源和骨架的 `spec_id` 永不相同，
所以「复用平台 id」策略实测复用数为 **0**，必然全部新建。

另外确认：`id: 0` / `sku_id: 0` 能让 `600123 规格信息不合法` 消失，
说明新建 SKU 的正确写法是显式 0，**不是省略字段**。

## 三、修掉一个会批量造废品的 bug（重要）

第一次测试时出现了这个：

```
"SKU 整树替换: 64 → 44（复用平台 id 0，新建 44）"
"保存: 操作过于频繁, 请稍后再试（2000000）"     ← 保存失败了
"提交: ok"                                     ← 但流程仍然提交了
```

结果：目标店多了一条**标题是源商品、SKU 是骨架的**商品。
如果这是批量任务，50 个商品会全部变成这种废品。

已修，两处：

### ① 保存失败必须阻断提交

```js
if (!saveOk) {
  return {
    ok: false,
    error: '草稿保存失败，已停止（未提交）',
    failed: 'failed_unknown',        // 按 AGENTS.md §5：状态未知，只许人工核对
    advice: '草稿仍留在目标店草稿箱：commit=... goods=...',
    steps,
  };
}
```

### ② 频控（2000000）自动重试一次

```js
if (!saveOk && /操作过于频繁|2000000/.test(...)) {
  await sleep(9000);
  sv = await runInMall(...);      // 实测有效
}
```

实测第二轮：

```
"保存: 操作过于频繁"        ← 第一次失败
"触发频控，等 9 秒后重试保存 ..."
"重试保存: ok"             ← 重试成功
"提交: 规格信息不合法 600123"
```

流程正确了：频控不再是静默失败，而是重试后继续。

## 四、跨店搬 SKU 规格的正确路径

只剩一条：**在目标店「从零新建商品」**，而不是克隆骨架。

```
现有（错）：目标店克隆自己的商品 → 规格被锁死 → 覆盖无效
应该（对）：目标店走 goods/add 新建 → 规格空白 → 自由填源的规格
```

新建页的初始状态规格是空的，那时候：
1. 填类目（`cat_id` + `goods_properties`）
2. **添加规格类型**（颜色 / 鞋码）→ 这一步是关键接口，本次没抓到
3. 填规格值 → 自动生成 SKU 矩阵
4. 填每个 SKU 的价格 / 库存 / 图片
5. 尺码表（接口已通，`sizespec/action/post`）
6. 保存 → 提交

**缺的就是第 2 步的接口。** 下次探测：刷新页面 → 点「添加规格类型」→
抓它发的请求。这次被残留弹窗挡了。

**工作量评估**：新建路径比克隆路径代码量大约 3 倍（要自己拼完整的
`goods_properties` 29 个属性 + 规格矩阵 + 尺码表），但这是唯一正确的路。
