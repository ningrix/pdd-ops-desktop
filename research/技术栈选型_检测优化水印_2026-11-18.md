## 一、先说最终选型

```
┌─────────────────────────────────────────────┐
│  Electron 主进程 (Node 22)                   │
│    ├─ 规则检测：纯 JS，不算图                │
│    └─ spawn ─────────────────────┐          │
└───────────────────────────────────┼─────────┘
                                    ↓
┌─────────────────────────────────────────────┐
│  Python 3.12 子进程（统一 CLI）              │
│    imgtool watermark | clean | upscale | inspect │
│    stdout 输出 JSON，主进程解析              │
└─────────────────────────────────────────────┘
```

**一句话：图像走 Python 子进程，规则检测留在 Node。不装任何需要本地编译的东西。**

## 二、为什么图像必须走 Python（不是偏好，是硬约束）

## 三、三个功能的技术方案

### 1️⃣ 主图水印 —— 最简单，Pillow 就够

**不用引入任何新库**（PIL 已有）。

```python
# 核心就这几行
from PIL import Image, ImageDraw, ImageFont
draw = ImageDraw.Draw(img, 'RGBA')
draw.text((x, y), text, font=font, fill=(255,255,255,90))
```

**要实现的三种模式**：

| 模式 | 说明 | 适用 |
|---|---|---|
| 角标 | 右下角固定位置，单条文字 | 品牌标 |
| 平铺 | 斜向重复，低透明度 | 防盗图 |
| 卖点条 | 底部/顶部色带 + 文字 | 「顺丰包邮」「7天无理由」 |

**实测过的关键参数**（从你之前 290 张成品图反推的风格）：

```
透明度    0.28~0.35   太高遮挡商品，太低看不见
字号      图宽的 3.5%~5%
留白      距边 图宽的 2.5%
字体      思源黑体 / 系统微软雅黑
```

⚠️ **必须明确的一条**（AGENTS.md §1.2.6）：
水印**不能**用来躲重复铺货判定——平台算感知哈希，加字不影响。
它的正当用途是：品牌标、卖点角标、遮友商 logo。

### 2️⃣ 主图优化 —— 复用已有模型，但要**手写 RRDBNet**

这是技术栈里唯一的技术决策点。

#### 超分：不装 basicsr，自己写 80 行

`RealESRGAN_x4plus.pth` 是标准 **RRDBNet**，实测键名确认：

```
conv_first.weight      (64, 3, 3, 3)
body.0.rdb1.conv1...   → body 共 23 个 block
body.N.rdb1~rdb3       → 每个 block 3 个 RDB
conv_body / conv_up1 / conv_up2 / conv_hr / conv_last
参数：num_feat=64, num_block=23, num_grow_ch=32, scale=4
```

**这意味着**：不用装 `basicsr`（它依赖 filterpy、opencv-headless，且在新版 torch 上兼容性差），
我用纯 `torch.nn` 手写 RRDBNet 结构，直接 `load_state_dict` 就能跑。

≈ 80 行代码，零新依赖。

#### 去水印/去标：LaMa 已有，但预处理自己写

`big-lama-torchscript.pt` 已能加载。缺的是 `prepare_img_and_mask`（预处理）：

```python
# 标准 LaMa 预处理，约 30 行，不需要 simple_lama_inpainting 包
def prepare(img, mask):
    # 1. pad 到 8 的整数倍（模型要求）
    # 2. 转 float32 / 255，归一化
    # 3. mask 转 0/1，反转（LaMa 约定 1=要填）
    # 4. 转 tensor 加 batch 维
```

省一个包，也避免它的版本冲突。

#### 文字/logo 定位：装 rapidocr（唯一要装的）

```bash
pip install rapidocr-onnxruntime==1.4.4
```

| 项 | 值 |
|---|---|
| 依赖 | onnxruntime（**预编译 wheel，不需本地编译器**） |
| 体积 | 约 65 MB（含 PP-OCR 模型） |
| 用途 | 找出图上所有文字 → 生成 mask → 交给 LaMa 修补 |

**这符合 AGENTS.md §1.3.4**：要的是"不需要本地编译器"，onnxruntime 是预编译的。

### 3️⃣ 商品检测 —— 分两层，一层都不用装东西

#### 第一层：规则检测（纯 Node，0 依赖）

数据全在载荷里，不需要读图：

| 检查项 | 数据来源 | 判定 |
|---|---|---|
| 必填属性缺失 | `pdd.goods.cat.rule.get {cat_id}` vs 商品 `goods_properties` | 直接比对 |
| 标题超长 | `goods_name.length > 60` | 字符数 |
| 标题堆砌 | 重复词/违禁词 | 正则 + 词表 |
| SKU 完整性 | 每个 sku 有无 `multi_price`/`price`/`quantity_delta`/`thumb_url` | 逐条校验 |
| 价格逻辑 | `market_price > max(price)` 严格大于 | 数值比对 |
| 满件折扣 | `two_pieces_discount` 是否存在 | 类目要求 |
| 尺码表 | `size_spec_id` 是否为空 | 类目要求 |

**这一层能覆盖尘牛「商品检测」的 70%**，而且完全不需要图像。

#### 第二层：图像检测（Python，用 PIL，不用装新东西）

| 检查项 | 方法 | 阈值 |
|---|---|---|
| 尺寸 | PIL 读宽高 | ≥ 480×480 |
| 比例 | w/h | 1:1 为主图 |
| 体积 | 文件大小 | ≤ 1 MB |
| 白底纯度 | 四角 + 边缘采样，算接近白色的比例 | ≥ 70% |
| 文字覆盖 | rapidocr 的框面积 / 总面积 | ≤ 15% |
| 主体居中 | 非白像素的重心偏离中心距离 | ≤ 图宽 10% |

## 四、目录结构与接口约定

### 目录

```
app/                              # Electron
├─ lib/
│  ├─ inspect.js                  # 规则检测（新增，纯 Node）
│  └─ imgtool.js                  # spawn Python 的封装（新增）
└─ ...

tools/imgtool/                    # 新增，Python 包
├─ __main__.py                    # CLI 入口，argparse
├─ watermark.py                   # 三种水印模式
├─ clean.py                       # LaMa 去水印/去标
├─ upscale.py                     # RRDBNet 超分（手写）
├─ inspect_img.py                 # 图像检测
├─ models.py                      # RRDBNet 结构定义 + 加载器
└─ common.py                      # 预处理、JSON 输出、异常包装

work/models/                      # 已有，复用
├─ big-lama-torchscript.pt
└─ RealESRGAN_x4plus.pth
```

### CLI 约定（关键：统一 JSON 输出）

```bash
# 全部子命令都支持 --json，输出到 stdout，日志到 stderr
python -m tools.imgtool watermark \
  --in a.jpg --out b.jpg --mode corner \
  --text "XX户外旗舰店" --opacity 0.32 --json
# → {"ok":true,"out":"b.jpg","w":1200,"h":1200,"ms":180}

python -m tools.imgtool clean --in a.jpg --out b.jpg --auto-text --json
python -m tools.imgtool upscale --in a.jpg --out b.jpg --scale 4 --json
python -m tools.imgtool inspect --in a.jpg --json
# → {"ok":true,"w":800,"h":800,"whiteRatio":0.78,"issues":[...]}
```

**为什么用 CLI 而不是 HTTP 服务**：
- 无端口占用、无进程生命周期管理
- 失败即退出码，天然契合 `failed_known` / `failed_unknown` 分类
- 定时任务、脚本调用都方便

### Node 侧封装

```js
// app/lib/imgtool.js
function runImgTool(sub, args, timeoutMs = 120000) {
  // spawn python，只读 stdout 的 JSON
  // 退出码 != 0 → { ok:false, failed:'failed_known', error }
  // 超时 → { ok:false, failed:'failed_unknown' }   ← 按 AGENTS.md §5
}
```

⚠️ **注意**：`app/lib/imgtool.js` 要 spawn 子进程，
但 Electron 沙箱下 `child_process` 只能在主进程用 —— 这符合我们现有架构（全部 IPC 在主进程）。

| 项 | 状态 | 处理 |

## 八、一句话

> **技术栈：Node 管规则，Python 管子图；两者用 JSON-over-stdout 通信。**
> 只装 `rapidocr-onnxruntime` 一个包，其余复用已有的 torch + PIL + cv2 + 两个本地模型。
>
> 超分不装 basicsr（手写 80 行 RRDBNet），去水印不装 simple-lama（手写 30 行预处理）——
> 都是为了守住「不引入需要编译/重型依赖」这条硬约束。
